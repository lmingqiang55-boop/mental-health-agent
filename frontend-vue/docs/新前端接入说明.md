## 1. 系统组成与运行

后端不是单独一个进程，联调时需要同时存在 4 个进程：

| 进程 | 地址 | 作用 |
| --- | --- | --- |
| Ollama 本地模型 | `127.0.0.1:11434` | 决策模型底座 |
| 决策模型隧道 | 转发到 `127.0.0.1:8001` | 把 Ollama 暴露成 OpenAI 兼容接口，供后端 `POLICY_API_BASE_URL` 调用 |
| 后端 FastAPI | `127.0.0.1:8000` | 全部业务接口 |
| 前端静态服务 | 自选（旧原型 `127.0.0.1:8766`） | 托管你的新前端页面 |

### 1.1 启动后端（隧道 + API）

cwd 必须是 `backend/` 目录，且要用统一的 Conda 环境 Python：

```powershell
cd e:\Desktop\全球校园人工智能算法精英大赛AIC\backend
E:\app\Anaconda\envs\mental-health-agent\python.exe scripts/start_dev.py --policy-source local --skip-install
```

要点：

- 该脚本**只启动「决策模型隧道 + 后端」**，**不启动前端**。（脚本文末打印的 `cd frontend; npm run dev → 5173` 是过时提示，与本项目当前原型无关，忽略即可。）
- **冷启动慢**：后端启动时会加载 SenseVoice ASR 模型（modelscope），约需 **1 分钟**；这段时间端口 8000 尚未监听，请求会「无法连接」。请等到日志出现 `Application startup complete` 再开始调接口。
- `GET /api/health` 只表示 HTTP 服务起来了，**不代表 ASR 就绪**；ASR 是否可用要看 `GET /api/audio/status`。

### 1.2 启动前端静态服务

旧原型用：

```powershell
cd e:\Desktop\全球校园人工智能算法精英大赛AIC\旧UI\xinqing-prototype
node StartServer.js   # 监听 8766
```

新前端可以用任意技术栈 / 任意端口；**但必须把新端口加入后端 CORS 白名单**（见 1.3）。

### 1.3 CORS（关键，改完要重启后端）

后端从 `backend/.env` 的 `CORS_ORIGINS` 读取白名单（逗号分隔）：

```dotenv
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173,http://localhost:8766,http://127.0.0.1:8766,null
```

- `allow_credentials=False`（**不使用 Cookie / 不带凭证**）。
- 允许方法：`GET / POST / PUT / DELETE`。
- 允许请求头：**只有 `Content-Type`**（不要发自定义头，如 `Authorization`，会被拦）。
- `null` 用于「直接双击 HTML 用 `file://` 打开」时浏览器发出的 Origin。
- **修改 `.env` 后必须重启后端**才生效（`.env` 在后端导入期读取）。

## 2. 全局约定（先读这一节）

### 2.1 基础地址与协议

- Base URL：`http://127.0.0.1:8000`
- 交互式文档（可在线试接口）：`http://127.0.0.1:8000/docs`
- 除「音频上传」用 `multipart/form-data` 外，其余一律 `Content-Type: application/json`。

### 2.2 身份与鉴权

- **没有登录、没有 Token、没有 Cookie。** 不要发 `Authorization` 头（不在 CORS 允许头里）。
- 身份用**匿名学生标识 `student_ref`**：
  - 格式约束：`^[A-Za-z0-9_-]+$`，长度 1~128。
  - 由前端生成一次，存 `localStorage`，**跨会话复用**——它决定「历史记录」归属。
  - 不是登录凭据，换浏览器/清缓存即得到新身份。
- `session_id` 是**会话定位符，不是身份凭据**，服务端内存态，TTL 2 小时，重启即清空。

### 2.3 响应与错误

- 后端返回的是**裸 JSON**（业务对象本体），**不是** `{code,data,message}` 包裹。
  - 旧原型是在自己的 `api.js` 里把裸 JSON 包成 `{code,data,message}`；新前端**可以自行决定怎么封**。
- 错误统一格式：

```json
{ "error": { "code": "SESSION_NOT_FOUND", "message": "..." } }
```

- `RequestValidationError`（字段缺失/越界/类型错）统一返回 **422**：

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "Invalid request data." } }
```

- 常见错误码见 [4.x 各接口](#4-接口契约明细) 与 [5.4 错误码汇总](#54-错误码汇总)。

### 2.4 校验严格性

- 部分请求模型设置了 `extra="forbid"`：**多传一个未定义字段就会 422**。典型：
  `/api/vision/frame`、`/api/vision/capture`、`/api/vision/segment`、所有 `/api/healing/*` 请求。
- 空白字符串、`NaN/Infinity` 会被拒。
- 数字类型严格：`2.0` / `"2"` 这类可能被拒（如评分小项）。

### 2.5 时间与编码

- 时间统一 ISO 8601 字符串。
- 视觉/音频状态里的 `timestamp` 是**服务端 UTC**，**不能**替代前端采集时间 `captured_at_ms`。
- 全程 UTF-8；Windows PowerShell 控制台里中文可能显示乱码，但**数据本身是正确的**（用 Node/浏览器核对）。

## 4. 接口契约明细

### 4.1 健康检查

**GET `/api/health`** → `{"status": "ok"}`

### 4.2 Session

**POST `/api/session`**
请求（可空）：

```json
{ "student_ref": "a1b2c3d4" }
```

- 不传 `student_ref`：后端生成匿名标识。
- 传了：复用该标识（用于读取同一人的历史）。

响应 `CreateSessionResponse`：

```json
{
  "session_id": "uuid",
  "student_ref": "a1b2c3d4",
  "opening_message": "你好呀，我们先认识一下吧……",
  "status": "created"
}
```

- `opening_message` 显示即可；后端已把它存为**第一条助手消息**，不计入 `turn_count`。

**GET `/api/session/{session_id}`** → `SessionState`（见 [5.1](#51-sessionstate)）。不存在 → 404 `SESSION_NOT_FOUND`。

**DELETE `/api/session/{session_id}`** → `{"status": "deleted"}`

**PUT `/api/session/{session_id}/consent`**
请求：`{ "session_id": "...", "granted": true, "scope": ["screening","result_storage"] }`
响应 `ConsentResponse`：`{ "session_id": "...", "consent": { ... } }`

### 4.3 Chat（对话）

**POST `/api/chat`**
请求 `ChatRequest`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `session_id` | string | 是 | |
| `text` | string | 是 | 1~4000 字 |
| `vision_snapshot` | VisionState \| null | 否 | 与这句话**精确对齐**的视觉快照 |
| `utterance_id` | string | 否 | 本句唯一标识；重试复用可幂等 |
| `speech` | SpeechMetadata \| null | 否 | 提供时必须同时提供 `utterance_id` |

响应 `ChatResponse`（继承 `DialogueResponsePayload`）：

```json
{
  "session_id": "uuid",
  "reply": "听起来这段时间对你并不容易……",
  "next_strategy": "睡眠",
  "current_stage": "exploration",
  "risk": { "risk_level": "low", "risk_score": 0.1, "risk_reasons": [], "risk_types": [], "key_evidence": [], "requires_intervention": false },
  "turn_count": 1
}
```

约定：

- 前端**只显示 `reply`**，不要根据关键词自行决定下一问；下一问由后端决策模型给出。
- `next_strategy` 取值是 11 个动作之一：`其它 / 共情安慰 / 精神状态 / 睡眠 / 情绪 / 自杀倾向 / 躯体症状 / 食欲 / 社会功能 / 兴趣 / 筛查`（危机时为 `crisis_support`）。
- **对话没有自动结束信号**，评估必须由前端显式调用 `POST /api/assessment`。
- `utterance_id` 幂等：同会话同 `utterance_id`、内容完全一致的重试 → 返回首次成功响应，`turn_count` 不增加；内容任一变化 → 409 `UTTERANCE_CONFLICT`。
- 决策模型不可用 → 503 `POLICY_UNAVAILABLE`，本轮不落库。

### 4.4 Vision（视觉）

**POST `/api/vision`**（句级状态，merge 语义）
请求：

```json
{ "session_id": "...", "state": { "emotion": "sad", "valence": -0.4, "face_detected": true } }
```

响应 `StateUpsertResponse`：`{ "session_id": "...", "status": "updated", "vision_state": { ... } }`
只更新 `state` 里传入的字段，未传字段保持原值。

**POST `/api/vision/capture`**（开关采集，代次隔离）
请求：`{ "session_id": "...", "capture_id": "capture-1", "generation": 1, "active": true }`
- 关闭：`active=false` 且 `generation` 递增。
- 响应回显 `session_id / capture_id / generation`（关闭时 `capture_id=null`）。
- 过期的低 `generation` 命令不生效；同代次同内容可重试，不同内容 → 409 `VISION_CAPTURE_CONFLICT`。

**POST `/api/vision/frame`**（一帧即时分析，不落盘）
请求（**新旧两种，二选一**）：

```json
{ "session_id": "...", "image_base64": "data:image/jpeg;base64,..." }
```

```json
{
  "session_id": "...",
  "image_base64": "data:image/jpeg;base64,...",
  "frame_id": "frame-1",
  "capture_id": "capture-1",
  "captured_at_ms": 12500.5
}
```

- `frame_id / capture_id / captured_at_ms` **必须同时给或同时不给**。
- 带时间帧要求 `capture_id` 与当前活动采集一致。
- 限制：仅 JPEG/PNG，解码后像素数 ≤ `1920×1080`，否则 422 `INVALID_FRAME`。
- 错误：409 `VISION_CAPTURE_INACTIVE`（旧帧/采集未开）、409 `VISION_FRAME_CONFLICT`（同 `frame_id` 改内容）、503 `VISION_UNAVAILABLE`。
- 响应 `VisionFrameResponse`：在 `vision_state` 之外回显 `frame_id / capture_id / captured_at_ms`。

**POST `/api/vision/segment`**（按发言区间聚合，冻结快照）
请求：

```json
{ "session_id": "...", "utterance_id": "u1", "capture_id": "capture-1", "start_ms": 12000, "end_ms": 16800 }
```

- 区间须正时长且 ≤ **60000ms**。
- 响应 `VisionSegmentResponse`：`{ session_id, utterance_id, capture_id, start_ms, end_ms, frame_count, valid_frame_count, vision_snapshot }`
- 首次结果冻结；重试不吸收晚到帧；改区间 → 409 `UTTERANCE_CONFLICT`。无帧时 `vision_snapshot=null`。
- 聊天要复用它拿到的 `vision_snapshot`。

### 4.5 Audio（语音）

**GET `/api/audio/status`** →

```json
{
  "state": "ready", "provider": "sensevoice", "model": "iic/SenseVoiceSmall",
  "max_upload_bytes": 10485760, "max_duration_seconds": 60,
  "timeout_seconds": 60, "max_pending": 4,
  "supported_mime_types": ["audio/wav", "audio/mpeg", "..."]
}
```

**POST `/api/audio/transcribe`**（`multipart/form-data`）
FormData 字段：`file`、`session_id`、`utterance_id`、`capture_id`、`recording_start_ms`、`recording_end_ms`。
- **只转写**，不改 `turn_count`、不存原始音频、不创建聊天回合。
- 转写成功后，前端需**自己再调一次 `/api/chat`**，带上返回的 `utterance_id` 与 `speech`（本句有视觉则带 `vision_snapshot`，没有则省略）。
- 限制：默认 ≤60s、≤10MiB。
- 错误：415 `UNSUPPORTED_AUDIO_FORMAT`、413 `AUDIO_TOO_LARGE`、422 `INVALID_AUDIO / AUDIO_TOO_LONG / AUDIO_TIME_MISMATCH / NO_SPEECH / TRANSCRIPT_TOO_LONG`、503 `ASR_UNAVAILABLE / ASR_BUSY`、504 `ASR_TIMEOUT`。
- 响应 `TranscriptionResponse`：`{ session_id, utterance_id, text, speech: {...} }`

**POST `/api/audio`**（句级音频状态，merge，可选）
`{ "session_id": "...", "state": { "speech_rate": 0.7, "energy": 0.4, "audio_available": true } }`

### 4.6 TTS（语音播报）

**GET `/api/tts/status`** → `{ "state": "ready | unconfigured", "model": "...", "voice": "..." }`（仅表示密钥/空间是否配置）

**POST `/api/tts`**
请求：`{ "session_id": "...", "turn_count": 1 }`
- `turn_count=0` → 合成新会话开场白；`1` 及以上 → 合成对应回合的助手回复。
- 成功返回**二进制 `audio/mpeg`**（`Cache-Control: no-store`）。前端拿到后用 `Blob` + `Audio` 播放。
- 后端只读已保存的助手文本；密钥不返回浏览器。
- 错误：404 `REPLY_NOT_FOUND`、422 `INVALID_TTS_TEXT`、503 `TTS_UNAVAILABLE`。

### 4.7 Assessment（评估）

**POST `/api/assessment`**（**唯一评估入口**）
请求：

```json
{ "session_id": "...", "evaluation_input": null }
```

- 一般只传 `session_id` 即可；服务端从已保存消息与绑定快照构造输入。
- 也可由上游显式提供 `evaluation_input`（结构见 `api_spec.md` 第 4 节）。

响应 `AssessmentResponse`：`{ "session_id": "...", "status": "completed", "result": EvaluationResult }`
`EvaluationResult` 关键字段见 [5.2](#52-evaluationresult评估结果)。
错误：422 `INVALID_EVALUATION_INPUT`、503 `EVALUATION_UNAVAILABLE`、409 `HISTORY_CONFLICT`。

**GET `/api/assessment/result/{result_id}?session_id=...`** → 同结构；404 `RESULT_NOT_FOUND`。
> 注意：读结果**必须同时给 `result_id` 和 `session_id`**。

### 4.8 History（学生历史）

**GET `/api/history/{student_ref}`** → `{ "student_ref": "...", "records": [EvaluationRecord...], "total": 3 }`
每个 `student_ref` 只保留**最近 3 次**，持久化在 SQLite，重启不丢。

### 4.9 Healing（治愈陪伴，#13）

**POST `/api/healing/start`**
请求 `StartHealingRequest`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `session_id` | string | 是 | 需已有评估记录 |
| `request_id` | string | 是 | 幂等标识（≤128，非空白） |
| `regenerate` | bool | 否 | 默认 `false`；重新生成时才绑定最新评估 |
| `expected_healing_id` | string | 否 | 状态变更保护 |
| `background` | object | 否 | 见下 |

`background`（`HealingBackgroundInput`，`extra=forbid`）：`school_stage`（`primary/middle/high`）、`current_concern`、`important_events[]`、`preferences[]`、`constraints[]`、`previous_attempts[]`、`adult_support_available`。
> **年龄不从这里传**（`age` 字段已移除，显式传入会 422）。年龄从最新持久评估的 `result.age` 读取。

响应 `HealingResponse`（见 [5.3](#53-healingresponse治愈响应)）。
错误：404 `HEALING_SESSION_EXPIRED` / `HEALING_NOT_FOUND`、409 `HEALING_REQUEST_CONFLICT` / `HEALING_STATE_CHANGED` / `HEALING_ASSESSMENT_REQUIRED` / `HEALING_ENDED` / `HEALING_TURN_LIMIT`、422 `VALIDATION_ERROR`、503 `HEALING_BUSY` / `HEALING_UNAVAILABLE`。

**GET `/api/healing/{session_id}`** → `HealingResponse`（刷新后取回当前陪伴状态）。

**POST `/api/healing/chat`**
请求：`{ "session_id": "...", "healing_id": "...", "message_id": "...", "text": "..." }`（`message_id` 幂等）
→ `HealingResponse`。

> **重要**：治愈陪伴状态是**进程内存**，**仅当前会话有效**；刷新页面/重启服务会失效（响应里的 `notice` 会提示）。学生视图**不含**内部证据/知识来源。

### 4.10 Heal 小工具（治愈航线自查工具，独立于 #13）

> 按匿名 `student_ref` 落库，持久化在 `backend/data/heal_journal.sqlite3`，刷新/重启不丢。

**GET `/api/heal/contents?mood=3&tag=焦虑`**

## 5. 数据模型速查

### 5.1 SessionState

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `session_id` | string | 会话 ID（UUID） |
| `student_ref` | string \| null | 匿名学生标识 |
| `conversation_history` | Message[] | 完整对话历史（首条为固定开场白） |
| `turn_count` | int | 已完成回合数（不含开场白） |
| `current_stage` | enum | `exploration / crisis / assessment / completed` |
| `latest_vision_state` | VisionState \| null | 最新视觉状态 |
| `latest_audio_state` | AudioState \| null | 最新音频状态 |
| `vision_state_log` | VisionState[] | 视觉状态日志 |
| `audio_state_log` | AudioState[] | 音频状态日志 |
| `vision_summary` / `audio_summary` | Summary \| null | 会话级汇总 |
| `latest_risk` | RiskResult | 最新风险 |
| `crisis_mode` | bool | 是否危机模式 |
| `consent` | ConsentRecord | 知情同意 |
| `assessment_result_id` | string \| null | 关联评估结果 ID |
| `created_at` / `updated_at` | datetime | 时间戳 |

`Message`：`{ role(user/assistant/counselor/system), content, created_at, vision_snapshot?, audio_snapshot?, utterance_id?, speech? }`

`VisionState` 数值字段（全部可选，null 表示无数据）：`emotion`、`emotion_confidence`(0~1)、`valence`(-1~1)、`arousal`(0~1)、`engagement`(0~1)、`attention_score`(0~1)、`gaze_focus`(0~1)、`micro_expression_intensity`(0~1)、`face_detected`(bool)、`timestamp`。

`AudioState`：`text`、`speech_rate`、`pause_ratio`、`energy`、`pitch_mean`、`pitch_variability`、`audio_available`(bool)、`timestamp`。

`RiskResult`：`{ risk_level(low/medium/high), risk_score(0~1), risk_reasons[], risk_types[], key_evidence[], requires_intervention(bool) }`

### 5.2 EvaluationResult（评估结果）

| 字段 | 说明 |
| --- | --- |
| `result_id` | 评估结果唯一 ID |
| `session_id` / `student_ref` | 归属 |
| `age` / `grade` | 用户首句明确说明的年龄/年级（可能为 null） |
| `psychological_profile` | 五维画像，各维 **0~100** |
| `concern_index` | 关注指数 **0~100** |
| `overall_level` | `low_concern / mild_concern / moderate_concern / high_concern` |
| `risk` | `RiskResult` |
| `report` | 报告主体，见下 |
| `assessment_method` | 固定 `"evaluation_agent"` |
| `created_at` | 生成时间 |

五维键：`emotion`(情绪状态)、`interest_motivation`(兴趣与动力)、`sleep_energy`(睡眠与精力)、`attention_thinking`(专注与思考)、`social_daily`(社交与日常功能)。
**方向：数值越高 = 该维度值得关注的信号越突出**（不是「越高越好」）。

`report` 固定 6 个区块 + 1 个技术字段：

1. `overall_status`：`{ level, concern_index, summary }`
2. `psychological_profile`：五维（与顶层一致）
3. `primary_concern`：`{ dimension(五维之一), description }`
4. `key_findings`：`[{ title, description }]`（**2~4 条**）
5. `multimodal_observation`：`{ consistency_score(0~100 或 null), consistency_level(low/moderate/high/unknown), summary }`
6. `trend_and_suggestions`：`{ trend(improving/stable/fluctuating/worsening/unclear), trend_summary, suggestions[] }`（**2~4 条**）
7. `metadata`：`{ schema_version:"1.0", assessment_id, generated_at }`（**不展示给普通用户**）

> `concern_index`、`level` 都是**派生值**（由五维算出），后端会校验一致性，不会自相矛盾。

  "healing_id": "...",
  "assessment_result_id": "...",
  "status": "active | paused | ended | referred",

## 6. 关键业务流程串联

### 6.1 心理筛查主链路（文字）

```
POST /api/session            → 拿 session_id / student_ref / opening_message
  └ 显示 opening_message
POST /api/chat               → 拿 reply / next_strategy / risk / turn_count（循环多轮）
  └ 显示 reply
POST /api/assessment         → 拿 result（EvaluationResult）
GET  /api/assessment/result/{result_id}?session_id=...   → 需要重新拉取结果时
GET  /api/history/{student_ref}                          → 历史记录
```

### 6.2 带语音/视觉的回合

```
（视觉）POST /api/vision/capture   → 开采集
        POST /api/vision/frame     → 反复送帧
        POST /api/vision/segment   → 回合结束按 [start_ms,end_ms) 冻结本句 vision_snapshot
（语音）POST /api/audio/transcribe → multipart 上传，拿 text + utterance_id + speech
        POST /api/chat             → 带 text / vision_snapshot / utterance_id / speech
```

- `segmented` 快照与 `speech` 的 `capture_id`、区间要一致。
- 没有视觉就**省略** `vision_snapshot`（不要拿「最近一帧」顶替）。

### 6.3 评估 → 治愈陪伴

```
GET  /api/history/{student_ref}   → 确认有评估记录（healing/start 需要）
POST /api/healing/start           → 拿 healing_id / report / messages
POST /api/healing/chat            → 循环多轮；每轮带 healing_id + message_id
GET  /api/healing/{session_id}    → 刷新后恢复当前陪伴
```

### 6.4 治愈小工具（独立，持久化）

```
GET  /api/heal/contents           → 工具箱内容 + 标签
POST /api/heal/mood  / GET /api/heal/mood
POST /api/heal/habits / GET /api/heal/habits
POST /api/heal/focus  / GET /api/heal/focus
GET  /api/heal/growth             → 汇总
```

### 6.5 老师端 / 沟通

```
GET  /api/teacher/records | /records/{id} | /student/{ref} | /high-risk | /group-stats
POST /api/teacher/records/{id}/notes
POST /api/communication          → 发消息
GET  /api/communication/{ref}    → 取消息
```

## 8. 对接技术陷阱（非设计建议）

1. **CORS 改白名单后要重启后端**，否则新端口仍被拦。
2. **只允许 `Content-Type` 请求头**：不要加 `Authorization` 等自定义头。
3. **`useBackend` 之类开关是你的自由度**：后端无 mock，全部接口都是真实实现。
4. **`/api/audio/transcribe` 是 multipart**：用 `FormData`，**不要手动设 `Content-Type`**（boundary 由浏览器加）。
5. **`/api/tts` 返回二进制**：用 `response.blob()`，不是 `.json()`。
6. **`/api/assessment/result` 需要两个参数**：`result_id`（路径）+ `session_id`（查询串）。前端需自行保存 `result_id → session_id` 映射。
7. **`session_id` 内存态、TTL 2 小时、重启清空**；`/api/heal/*` 与 `/api/history` 落 SQLite，持久。
8. **没有「结束对话」接口**：评估必须显式调 `POST /api/assessment`。
9. **幂等标识**：`utterance_id`（chat）、`message_id`（healing/chat）、`request_id`（healing/start）——重试时应**复用同一个**，内容变了会 409。
10. **`extra=forbid` 接口不要多传字段**，否则 422（视/帧/采集/segment/所有 healing）。
11. **`healing/start` 不要传 `age`**（已移除，传了报 422）；年龄由后端从最新评估读。
12. **数值方向语义**：评估五维/`concern_index` 越大 = 越值得关注；`consistency_score` 越大 = 语言与视觉越一致。
13. **`/api/teacher/*` 无鉴权**，且是骨架，接之前先实调确认字段。
14. **冷启动**：后端 1 分钟内 8000 未监听；`/api/health=ok` ≠ ASR 就绪（用 `/api/audio/status`）。
15. **`student_ref` 必须匹配 `^[A-Za-z0-9_-]+$`**，不合法会在 `GET /api/heal/*` 等处被 422 拒。
