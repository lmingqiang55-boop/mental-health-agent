# 学生端规划 · 结合「新方案 + 旧方案」的最终方案

> **本文定位**：把「你给出的学生端新方案（功能树 / 测评五步流程 / IA）」与「旧方案（旧原型 `旧UI/xinqing-prototype/*` + 现有后端真实契约）」合成一份**可执行的最终规划**，然后据此动手做前端。
> **核心结论先说**：
> 1. **测评主链路（会话→语音→对话→评估→报告）与治愈陪伴（#13）后端现成可用**，是本次能真正「接上后端」的部分，作为 MVP 主干。
> 2. **治愈 13 功能里，「治愈陪伴 / 心情日记 / 专注学习 / 成长回顾 / 工具箱内容」有后端接口**；iCBT 单元已补齐后端（`/api/heal/icbt`，单元目录 + 学生完成度），同伴支持社区、艺术表达等要么后端没有、要么纯前端实现。
> 3. **「我的」模块（个人档案 / 咨询预约 / 紧急联系人 / 消息中心）后端几乎为零**，本期用「本地存储 + 占位」实现；其中**咨询预约已补齐后端**（`/api/counseling/appointments`，与管理端数据互通），失败时本地降级。
> 4. 学生端与管理端是**两个独立工程**：管理端 `新前端/admin`（端口 5173），学生端 `新前端/student`（端口 **5174，必须加进后端 CORS 白名单**）。
> **事实来源**：`新前端/docs/新前端接入说明.md`（后端契约）、`backend/backend/api/*`、旧原型 `旧UI/xinqing-prototype/*`、旧规范 `旧UI/旧/心晴-前端设计与开发规范.md`。文档与代码冲突时**以代码为准**。
> **前提**：无鉴权；身份用匿名 `student_ref`（`^[A-Za-z0-9_-]+$`，1~128 位），存 `localStorage` 跨会话复用。

## 一、目标与硬约束

**学生端定位**：面向 12–20 岁青少年的「测评 + 治愈 + 陪伴」一体化入口，AI 助手叫「**小晴**」，网页名「**心晴**」。

**产品底线（沿用旧规范第 2.3 节，不可违反）**：

| 原则 | 学生端落点 |
| --- | --- |
| 四不承诺 | 不下诊断、不判断真假、不贴标签、不自动处置；报告页页脚固定展示 |
| 措辞规范 | 一律「初步筛查 / 关注提示 / 关注等级 / 状态较平稳…」；**禁止**「确诊抑郁症 / 患病概率」 |
| 知情同意（呈现型） | 测评前弹窗呈现协议，点「家长和学生已知情并同意」即进入；**不强制门控、不拦截路由** |
| 最小化数据 | 语音仅转写不留存、视频仅提特征；采集可见可控（摄像头/麦克风有关闭按钮） |
| 非医疗定位 | 全站免责声明 + 12356 热线入口 |

**必须正视的现状约束（来自后端代码）**：

1. **无鉴权**：没有 Token / Cookie / 角色。学生端身份 = `student_ref`，前端生成并持久化。
2. **会话/治愈陪伴是进程内存**：`session_id`、`healing_id` TTL 2 小时，**重启即清空**；只有 `/api/history` 与 `/api/heal/*` 落 SQLite 持久。
3. **`history` 只保留最近 3 次**：趋势页最多展示 3 个点，需队友放宽后才能长趋势。
4. **后端是「对话式评估」而非量表**：接口叫 PHQ-9 但后端实际是 `evaluation_agent`（对话五维 + 关注指数 + 风险），**没有题干/选项/逐题计分**。前端按「对话式测评」实现，不假装有量表题。
5. **CORS 只允许 `Content-Type` 头**（`allow_credentials=False`）：新端口 5174 必须加进 `CORS_ORIGINS`；改 `.env` 后**重启后端**。
6. **`extra="forbid"`**：`/api/vision/*`、所有 `/api/healing/*` 多传字段即 422，请求体别夹带 UI 字段。
7. **评估必须显式触发**：对话无「自动结束」信号；结束对话后由前端调 `POST /api/assessment`。
8. **治愈陪伴需要先有评估**：`/api/healing/start` 要求该 `session_id` 已有评估记录；且**不要传 `age`**（会 422）。

| 维度 | 你的新方案（用户） | 旧方案（原型 + 后端） | 最终方案（合并取舍） |

| 技术栈 | （未指定，倾向与 admin 一致） | 纯静态 MPA + 全局命名空间 | **Vue3 + TS + Vite + Pinia + Vue Router + Axios + Dayjs**（与 admin 同栈）；图表用 ECharts 按需懒加载 |

## 五、测评主链路（详细，接后端）

沿用旧原型 `api.js` 的真实链路（`sendVoice` / `synthesize` / `syncConsent`），在 Vue 中以 composables 重写：

```text
① 创建会话      POST /api/session                       → session_id, student_ref, opening_message
② 知情同意      PUT  /api/session/{id}/consent          → { granted:true, scope:["screening","result_storage"] }
③ 设备检查      getUserMedia（本地态，不上传）
④ 对话循环：
   - 开场白播报  POST /api/tts {turn_count:0}            → audio/mpeg（Blob 播放）
   - 点「开始说话」开始录音（MediaRecorder）
   - 点「结束」：
       a. 视觉段   POST /api/vision/segment             → vision_snapshot（若开摄像头）
       b. 转写     POST /api/audio/transcribe（multipart）→ text + speech
       c. 对话     POST /api/chat {utterance_id, text, speech, vision_snapshot}
                                                        → reply, next_strategy, turn_count, risk
       d. 播报     POST /api/tts {turn_count}            → audio/mpeg 自动播放
⑤ 结束对话 → 安全检查  /assess/safety（若 reply.risk.requires_intervention → 求助卡）
⑥ 触发评估      POST /api/assessment                    → result.result_id
⑦ 拉报告        GET  /api/assessment/result/{result_id}?session_id=...  → EvaluationResult
```

**关键实现点（来自契约与旧原型）**：

1. **录音 → 转写 → 对话是三步**，转写不改 `turn_count`，必须前端再调一次 `/api/chat`。
2. `utterance_id` / `message_id` **幂等**：重试复用同 id + 同内容 → 不重复计数；内容变了 → 409。前端生成 id 后**本轮内保持稳定**。
3. **视觉可关**：关摄像头 → 不带 `vision_snapshot`；`sessionStorage.xq_device_cam=false` 仅前端态，**不影响评估有效性**。
4. **TTS 503 降级**：`POST /api/tts` 返回 503 时用浏览器 `speechSynthesis` 兜底；`GET /api/tts/status` 判断是否配置。
5. **麦克风不可用兜底**：旧原型用 `M.VOICE_SCRIPT.normal` 台词；新端保留「文本兜底」但不暴露给用户（仅在设备失败时提示）。
6. **报告字段隔离**：学生端**不展示** `student_ref` / `assessment_method` / `report.metadata` / `risk_score` / `key_evidence`；只展示叙述报告 6 区块 + 五维 + 关注指数 + 关注等级 + 风险提示。
7. **报告降级**：若 `report` 缺失 → 只渲染五维 + 关注指数 + 关注等级 + 风险提示，不报错、不留空。
8. **暂停续测（补做）**：`localStorage.xq_assess_progress = { sessionId, turnCount, lastUtteranceId, updatedAt }`；回到 `/assess/session/:id` 时先 `GET /api/session/{id}` 校验会话是否过期（404 → 提示重开）。
