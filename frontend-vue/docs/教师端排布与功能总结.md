# 教师端排布与功能总结

> **本文定位**：描述现有原型 `旧UI/xinqing-prototype/` 中**教师端的页面排布与功能**，并标注每项功能的**数据来源**（真实后端 / 前端派生 / 本地 mock）。
> **事实来源**：页面 HTML 代码、`api.js`、后端 `backend/backend/api/teacher.py`。文档与代码冲突时，以代码为准。
> **不含**界面 / 视觉 / 交互设计建议。
> **适用范围**：当前为**无鉴权框架骨架**，接入真实权限前不得连接真实学生数据。

---

## 一、页面清单与整体外壳

教师端共 **5 个页面**（4 个侧栏主视图 + 1 个详情页）：

| 页面 | 文件 | 作用 |
| --- | --- | --- |
| 工作台 | `teacher-dashboard.html` | 待办概览与近期动态，KPI 卡可直达各视图 |
| 个体筛查 | `teacher-individual.html` | 学生列表 + 多条件筛选 |
| 高风险预警 | `teacher-alerts.html` | 集中处置全部预警 |
| 群体统计 | `teacher-group.html` | 班级/年级整体心理状态与趋势 |
| 学生个体档案 | `teacher-individual-detail.html` | 单个学生的完整档案（详情页，非侧栏项） |

**统一外壳**（每页结构一致，`<body class="shell-teacher">`）：

```
win-desktop
 └ win-window
    ├ win-titlebar   标题栏：心形图标 +「心晴 · 教师端」+ 当前用户 + 头像 + 最小化/最大化/退出登录(data-logout)
    └ win-body
       ├ win-sidebar 左侧导航（4 项，见下）
       └ win-main    主区
```

**左侧导航**（四项固定，`data-nav` 与当前页 `data-page` 对应高亮）：

| 导航项 | `data-nav` | 跳转 |
| --- | --- | --- |
| 工作台 | `t-dashboard` | `teacher-dashboard.html` |
| 个体筛查 | `t-individual` | `teacher-individual.html` |
| 高风险预警 | `t-alerts` | `teacher-alerts.html`（带未处理预警数角标 `#navAlertBadge`） |
| 群体统计 | `t-group` | `teacher-group.html` |

> 每页首行执行 `A.requireRole("teacher")`，非教师角色被拦截；页脚统一引入 `mock.js` → `api.js` → `app.js`。

## 二、四个主视图

### 1) 工作台 `teacher-dashboard.html`

**排布（自上而下）**：

1. 页面标题 + 说明
2. **KPI 卡区**（`u-grid-4`，每张卡可点击跳转）
3. 测评覆盖率文案行
4. 最新预警（列表，前 4 条）
5. 待复核队列（表格，前 5 条）
6. 最近操作留痕（列表，5 条）
7. 加载失败兜底 `#errBox`

**功能与数据来源**：

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| KPI 卡 | 待复核报告 / 高风险学生 / 待处理预警 / 近 7 天新测评 | `Api.dashboard()`（后端无该接口，**前端由 `/api/teacher/records` 聚合**）+ `Api.alerts()` 统计 `state=open` |
| 覆盖率行 | 「初二年级整体测评覆盖率 NN%」 | `dashboard().coverage`（分母用本地花名册人数） |
| 最新预警 | 前 4 条，标签区分「安全题命中 / 高风险学生」，点击进详情 | `Api.alerts()` |
| 待复核队列 | 姓名/班级/风险徽章/关注徽章/最近测评 + 查看档案 | `Api.teacherStudents({grade:"初二"})`，筛 `reviewState=pending` |
| 操作留痕 | 操作人 · 动作 · 时间 | 本地 `M.opLog`（前端持久化） |

**跳转**：KPI 卡 → `teacher-individual.html?review=pending` / `?risk=high`、`teacher-alerts.html`、`teacher-individual.html`。

### 2) 个体筛查 `teacher-individual.html`

**排布**：

1. 标题 + 说明
2. **筛选表单** `#filterBar`：年级、班级、风险等级（低/中/高/待复核）、关注等级、关键词（姓名/学号）、查询、重置
3. 条件统计行 `#countLine`（共 N 人 · 高风险 N · 待复核 N）
4. **学生表格** `#tbl`：姓名 / 学号 / 班级 / 最近测评 / 风险等级 / 关注等级 / 复核状态 / 操作
5. 空态 `#emptyBox` / 失败态 `#errBox`

**功能与数据来源**：

- 列表：`Api.teacherStudents({grade, className, q})`；风险等级与关注等级筛选在**前端二次过滤**。
- URL 预置：`?risk=`、`?review=pending`、`?className=` 会自动填入对应筛选器。
- 行内操作：
  - **查看档案** → `teacher-individual-detail.html?id=...`
  - **发起复测** → `Api.reassess(id)`（**后端无此接口，仅本地建占位会话，不落后端**），带二次确认。

### 3) 高风险预警 `teacher-alerts.html`

**排布**：

1. 标题 + 说明（明确定位：预警是个体筛查的**风险视图**，非独立模块）
2. **筛选 tabs** `#filterTabs`：全部 / 高风险学生聚焦 / 安全题命中 / 待复核队列跳转
3. 预警列表 `#alertList`（圆点状态 + 姓名·班级 + 触发标签 + 关注徽章 + 状态标签 + 动作按钮 + 时间）
4. 空态 `#alertEmpty` / 失败态 `#errBox`

**功能与数据来源**：

- 列表：`Api.alerts({})`；按 `trigger` 前端过滤。
- 状态机：`open`(待处理) → `reviewing`(复核中) → `handled`(已处置)。
- 动作按钮（均二次确认）：**开始复核**(→reviewing)、**标记处置**(→handled) → `Api.updateAlertState()`。
- 点条目 → 学生详情页。

### 4) 群体统计 `teacher-group.html`

**排布**：

1. 标题 + 说明（群体数据**仅看整体、不呈现个体信息**）
2. 筛选表单：年级、班级、查询
3. **4 张指标卡**：已测人数、测评覆盖率、高风险人数、待复核报告
4. **四个图区**：
   - 风险分布（堆叠条 + 图例）
   - 近六周风险趋势（分周堆叠柱）
   - 五维均分（线性条）
   - 多模态观察占比（表情/视线，注明「语音仅转写、不计入占比」）
5. 失败态 `#errBox`

**功能与数据来源**：

- 主体：`Api.groupStats(grade, className)`。
- 待复核数：`Api.teacherStudents({grade, className})` 前端统计。

## 三、学生个体档案 `teacher-individual-detail.html`

由个体筛查表 / 预警 / 工作台点入，`?id=学生编号`。七个区块：

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| ① 概览 | 姓名 / 学号 / 班级 / 最近测评 / 关注等级 / 复核状态 | `Api.teacherReport(id)` + 本地花名册补全 |
| ② 风险评估 | 风险等级 / 评分 / 风险类型 / 判断依据；需干预时显示横幅 | `teacherReport().risk` |
| ③ 五维心理画像 | 五维线性条 | `dimensionScores`（缺失时由 `psychologicalProfile` 回退生成） |
| ④ 对话证据链 | 每轮：原句 + 表情线索 + 视线线索 + 关联维度，点条目展开 | `report.evidence`；**后端教师端不下发证据链，真实后端模式为空，不虚构** |
| ⑤ 复核与处置 | 改判风险等级 + 处置动作（持续关注/联系监护人/转介专业机构）+ 备注 → 提交复核 | `Api.submitReview()`（后端映射为写跟进备注，见下） |
| ⑥ 相关操作留痕 | 与该生相关的操作记录 | 本地 `M.opLog` 前端过滤 |
| ⑦ 与学生的沟通 | 老师 ⇄ 学生人工留言（与 AI 对话分开），回复最多 2000 字 | `Api.getMessages(id)` / `Api.sendMessage()`（`/api/communication`） |

**顶部预警横幅**：若该生存在未处置预警（`state != handled`），显示横幅并给出「前往预警通道」链接。

## 四、数据来源与后端对接（关键）

前端 `api.js` 教师端区块（约 `L1110–L1427`）的映射规则，决定了每块数据「真不真」：

**走真实后端**：

| 前端方法 | 后端接口 |
| --- | --- |
| `teacherStudents` | `GET /api/teacher/records` |
| `teacherReport` | `GET /api/teacher/student/{student_ref}` |
| `submitReview` | `POST /api/teacher/records/{record_id}/notes` |
| `groupStats` | `GET /api/teacher/group-stats` |
| `alerts` | `GET /api/teacher/high-risk`（派生） |
| `dashboard` | 无对应接口，**前端由 `/api/teacher/records` 聚合** |

**后端没有的，前端补齐 / 不编造**：

- **姓名 / 班级**：后端只持久化匿名 `student_ref`，无花名册；前端用**本地 mock 花名册**按 `student_ref` 匹配补全，匹配不到则用 `ref` 兜底。
- **`reviewState`（复核状态）**：由后端的 `follow_up_status` 派生（`pending`=待复核，其余=已复核）。
- **预警状态**：后端**无预警概念**；预警由「高风险名单」派生，状态机用 `localStorage`（键 `xq_alert_states`）维护。
- **发起复测**：后端无接口，后端模式下也走本地 mock，仅建占位会话、不落后端。
- **周趋势 / 多模态占比 / 对话证据链**：后端不提供，**一律留空，不虚构**。
- **操作留痕 `opLog`**：后端无全局操作日志，由前端持久化（跨页可见）。

> 后端 `teacher.py` 头部已注明：**当前无身份认证，是框架骨架；接入真实权限前不得连接真实学生数据。**

## 五、后端接口清单（`backend/backend/api/teacher.py`）

前缀 `/api/teacher`，共 6 条，**当前无鉴权**：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/teacher/records` | 全部记录摘要列表（`record_id / student_ref / concern_index / overall_level / risk_level / created_at / follow_up_status`） |
| GET | `/api/teacher/records/{record_id}` | 单条完整记录（不存在 → 404 `RECORD_NOT_FOUND`） |
| GET | `/api/teacher/student/{student_ref}` | 该学生全部记录 |
| GET | `/api/teacher/high-risk` | 中/高风险名单（含风险类型、原因、关键证据） |
| POST | `/api/teacher/records/{record_id}/notes` | `{ counselor_ref, content }` 添加跟进备注（会把 `follow_up_status` 置为 in_progress） |
| GET | `/api/teacher/group-stats` | 群体统计（全校聚合：`total_students / risk_distribution / dimension_averages`） |

## 六、已知缺口 / 注意事项

1. **无鉴权**：`/api/teacher/*` 是骨架，字段以实际返回为准，接入前先实调确认。
2. **后端无花名册 / 班级 / 预警 / 复测 / 趋势 / 多模态占比 / 证据链**：这些均由前端派生或留空（见第四节）。
3. **`group-stats` 不支持按班筛选**：后端为全校聚合，前端传的 `grade/className` 目前不生效。
4. **`dashboard` 无后端接口**：真实性取决于 `/api/teacher/records` 的返回，覆盖率分母用本地花名册人数。
5. 页面均与 `backend/docs/前端交接文档.md`、`backend/docs/api_spec.md` 可交叉核对。
