# 心晴 · 新管理端 对接文档

> **定位**：新前端的管理端（Vue 3 + TS + Vite），按 `新前端接入说明.md`（后端契约）与 `管理端规划.md`（功能规划）实现。
> **目录**：`frontend-vue/admin/`（工程）｜`frontend-vue/docs/`（本文 + 两份依据文档）

## 1. 启动

```powershell
# 1) 后端（须先启动，冷启动约 1 分钟，等 Application startup complete）
#    在项目根目录（本仓库 mental-health-agent/）执行
conda activate mental-health-agent
python scripts/start_dev.py --policy-source local --skip-install

# 2) 新管理端（端口固定 5173，已在后端 CORS 白名单）
cd frontend-vue/admin
npm install
npm run dev   # http://127.0.0.1:5173
```

- API 地址在 `.env.development` 的 `VITE_API_BASE`（默认 `http://127.0.0.1:8000`）。
- 顶栏右侧有「后端已连接/未连接」指示灯（`GET /api/health`）。

### 1.1 零依赖运行：直接双击 HTML

```powershell
cd frontend-vue/admin
npm run build
```

构建产物是**单个自包含文件** `frontend-vue\admin\dist\index.html`（JS/CSS 全部内联）。
双击即可打开，**不需要任何服务器**；接口照常访问 `http://127.0.0.1:8000`
（后端 `.env` 的 `CORS_ORIGINS` 已含 `null`，`file://` 页面可直接跨域调用）。

为此做了两处配置，改动时别退回去：

- `vite.config.ts`：`base: './'` + `viteSingleFile()` 插件（产物内联成单文件）。
- `src/router/index.ts`：路由用 **hash 模式**（地址形如 `index.html#/dashboard`），
  否则 `file://` 下路径路由会 404。

> 代价：改代码后必须重新 `npm run build` 才生效。开发阶段建议仍用 `npm run dev`（热更新）。

## 2. 技术栈

Vue 3 + TypeScript + Vite + Pinia + Vue Router + Element Plus + ECharts + Axios + Dayjs。
视觉遵循设计规范定稿：**纯白侧边栏 + 暖阳橙选中态、白底专业仪表盘、预警红黄绿分级**。

## 3.1 干预与咨询新增后端接口（本轮落地）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/counseling/appointments` | 预约列表，可选 `?student_ref=` |
| POST | `/api/counseling/appointments` | 创建预约（管理端直传 `slot`；学生端传 `date + preferred_label`，后端归一化为 `slot`） |
| POST | `/api/counseling/appointments/{id}/status` | 变更状态 `pending/confirmed/done/cancelled`（无 PATCH，故用 POST） |
| GET | `/api/heal/icbt/units` | iCBT 单元列表，附 `assigned/completed` 人数 |
| PUT | `/api/heal/icbt/units/{id}` | 部分更新单元（标题/模块/排序/步骤/时长/状态/人群） |
| GET/POST | `/api/heal/icbt/progress` | 学生 iCBT 完成度读写 |

- 学生端创建的预约只带 `student_ref`，后端会按学生档案（`profile_store`）补全 `student_name/class_name`，避免管理端「学生」列空白。
- 学生端「date + 时段文案」→ 后端 `normalize_slot` 合成 `slot='YYYY-MM-DD HH:MM'`，原文案存 `preferred_label` 供学生端回显。
- iCBT 单元目录由后端种子（`u1~u6`）初始化，与学生端本地单元 id 对齐；`completed` = 完成该单元的学生数，`assigned` = 有进度记录的学生数。

## 4. 对接契约要点（已在新端落实）

- **裸 JSON 响应**，错误体 `{error:{code,message}}`，422 = `VALIDATION_ERROR`（`src/api/http.ts` 拦截器统一解包 + 全局报错提示）。
- **不带任何自定义请求头**（后端 CORS 只允许 `Content-Type`）；将来后端加 Token 时，需同步把 `Authorization` 加进 `allow_headers`。
- 跟进备注走 `POST /api/teacher/records/{record_id}/notes`，提交后后端自动把跟进状态置为 `in_progress`。
- 学生档案每人**只保留最近 3 次**评估（后端 SQLite 上限），趋势图基于现有数据渲染。
- 管理端**不展示**原始聊天与原始音视频（本就无接口，符合数据原则）。
