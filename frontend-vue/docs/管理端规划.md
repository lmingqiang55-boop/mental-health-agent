# 管理端（原「教师端」）规划 · 结合旧端与现有后端

> **本文定位**：把「旧教师端（原型 + 现有后端接口）」与「你给出的管理端详细功能设计」合成一份**可执行的规划**。
> **核心结论先说**：你的功能设计里，**除了「个体档案 / 高风险名单 / 群体统计 / 跟进备注 / 人工沟通」这几块，现有后端几乎没有对应接口**——所以本规划的重点是「**功能 → 前端页面 → 需要什么后端接口**」的逐项对照，标出哪些现成可用、哪些必须让队友新增。
> **事实来源**：`backend/backend/api/*`、`backend/docs/api_spec.md`、旧原型 `旧UI/xinqing-prototype/teacher-*.html`、`api.js`。文档与代码冲突时以代码为准。
> **前提**：学生端与管理端拆成两个独立前端工程；学生端继续用现有 `/api/session·chat·vision·audio·assessment·healing·heal` 那套，管理端只读「脱敏摘要 / 可解释报告 / 预警 / 干预记录」。

## 一、目标与硬约束

**管理端定位**（沿用你的定义）：测评任务管理 + 预警处置闭环 + 学生心理档案 + iCBT/干预管理 + 统计决策 + 系统权限管理。

**数据原则**（你的，保留）：
- 原始音视频不展示、不存储、不上传；
- 多模态只输出脱敏特征与可解释摘要；
- 心理教师看专业报告，班主任只看脱敏概览；
- 管理层看统计、不看个体明细；
- 敏感操作全留审计日志。

**必须正视的现状约束**（来自代码）：
1. **没有身份认证**：现有 `/api/teacher/*` 是骨架，无 Token、无 Cookie、无角色。管理端的「登录 / 权限 / 数据范围」后端从零开始。
2. **没有花名册 / 组织架构**：后端只有匿名 `student_ref`，**没有姓名、班级、年级的存储**（年级仅来自学生自述的 `result.grade`）。你的「学校→年级→班级→学生」需要新建。
3. **没有量表和测评任务**：现有评估是**对话式**（`evaluation_agent`，输出五维画像 + 关注指数 + 风险），**没有 PHQ-9/GAD-7 这类量表**，也没有「创建/发布测评任务」的概念。
4. **没有预警实体**：现有只有 `/api/teacher/high-risk`（按 `risk_level` 现算的中/高风险名单），**没有预警对象、等级、状态机、通知记录**。
5. **存储边界**：评估记忆用 SQLite（每位学生**只留最近 3 次**，路径 `data/evaluation_memory.sqlite3`）；治愈小工具 SQLite（`data/heal_journal.sqlite3`）；会话/治愈陪伴是**进程内存，TTL 2 小时，重启即清空**。管理端需要的长期档案、审计、任务都必须新建持久化。
6. **CORS 只允许 `Content-Type` 请求头**（`backend/backend/main.py`）。你计划用 **Token 鉴权**——只要前端带 `Authorization` 头就会**预检失败**，后端必须把 `Authorization` 加进 `allow_headers`。这是最容易踩的坑。

**旧端可直接复用的资产**：
- 指标卡 / 折线 / 堆叠条 / 线性条等图表组件与配色（新端换 ECharts 重写，但布局逻辑可参考）；

**旧端要丢弃的**：
- localStorage 存预警状态、本地花名册（`mock.js`）、`requireRole` 那种前端假鉴权——新端全部改**后端真数据**。

## 四、角色 · 权限 · 数据范围

**设计原则（你的，保留）**：功能权限靠**角色**，可见范围靠**数据范围（scope）**，二者解耦。

**4 + 1 角色**：

| 角色 | 定位 | 工作台 | 默认 scope |
| --- | --- | --- | --- |
| 系统管理员 | IT/平台维护 | 系统管理 | 组织、用户、角色、日志 |
| 心理教师 | 心理中心专业干预 | 心理工作台 | 全校 / 指定学生 |
| 班主任 | 一线观察与关怀 | 班级工作台 | 本班 |
| 管理层 | 决策、督办、统计 | 管理看板 | 全校 / 年级 |
| 外聘咨询师（可选） | 按需授权 | 咨询工作台 | 指定学生 |

**scope 模型**：

```ts
scope: {
  type: 'school' | 'grade' | 'class' | 'students',
  ids: string[]      // grade/class/student 的 id 列表
}
```

**前端如何用 scope**（你的 5.4，保留并明确）：
- 筛选器默认值（如班主任默认锁定本班，不可改）；
- 列表请求参数（把 scope 拼进查询）；
- 看板标题（「初二年级整体」之类）；
- 管理层专属「数据范围切换器」。

> **务必记住：后端必须二次校验**。前端 scope 只是体验优化，不能当安全边界。

**权限矩阵**（你的，保留）：管理员=系统配置/用户/角色/审计；心理教师=创建测评/专业报告/预警处置/访谈/iCBT/统计；班主任=班级概览/脱敏概览/上报/关怀；管理层=统计/趋势/处置率/督办；外聘咨询师=授权学生信息/访谈记录；**所有角色都「不看原始聊天、不看原始音视频」**。

**落地精简（你的 7 条建议，采纳）**：默认只启用 4 角色；外聘咨询师作为可选；德育主任/年级组长不单建角色，用「管理层 + scope」解决；角色模板化；前端只判断 4 个角色，范围交给接口；后端二次校验；敏感页加水印 + 导出需审批；原始聊天/音视频永不进管理端。

## 五、功能 → 页面 → 后端接口 对照（核心）

图例：✅ 现有接口可直接支撑 ／ 🟡 现有接口需扩展或只能部分支撑 ／ ❌ 后端不存在，**必须新增**。

### 5.1 测评管理

| 功能 | 前端路由 | 后端现状 | 说明 |
| --- | --- | --- | --- |
| 测评任务列表/创建/详情/进度 | `/assessment/tasks*` | ❌ 新增 | 后端无「任务」概念，需建 `assessment_task` 表与 CRUD、发布、进度统计 |
| 结果列表（按风险/班级/年级筛选） | `/assessment/results` | 🟡 | 现有 `/api/teacher/records` 可做**底料**，但无班级/年级维度（无花名册），需新增筛选项 |
| 报告详情-专业版 | `/assessment/report/:studentId/:taskId` | 🟡 | 现有 `GET /api/assessment/result/{result_id}` 返回完整 `report` 六区块（overall_status / psychological_profile / primary_concern / key_findings / multimodal_observation / trend_and_suggestions），**可支撑专业版**；但需按 `studentId+taskId` 定位，且现有是「对话式评估」结果，非量表结果 |
| 报告详情-脱敏版 | 同上 | 🟡 | 后端需新增**脱敏版字段**（只给风险等级/建议动作/是否上报），或前端裁剪；**不要前端只做视觉裁剪就当脱敏**，敏感字段不该下发 |
| PHQ-9 / GAD-7 / PHQ-2 / GAD-2 量表 | — | ❌ 新增 | 现有评估是 `evaluation_agent` 对话式五维，**无量表**。需新增量表定义、作答、计分、第 9 题（自伤念头）阳性判定 |
| 多模态采集开关（默认关，需学生单独授权） | — | 🟡 | 现有 `vision/capture·frame·segment`、`audio/transcribe` 采集链存在，但没有「任务级授权开关」；授权当前仅 `PUT /api/session/{id}/consent`（`ConsentStatus`）。需扩展 |

> 关键决策点（需你与队友拍板）：**量表评估 与 现有对话式评估 是「并行两套」还是「对话式折算成量表口径」**？这决定报告页的数据结构。

### 6.8 面向现有后端的适配要点（新增，重要）

新端要接的是**现在这套后端**，务必遵守它的既有契约（详见 `新前端接入说明.md`）：

1. **Base URL**：`http://127.0.0.1:8000`；本地开发期 Vite 端口 `5173` **已在 `CORS_ORIGINS` 白名单内**。
2. **鉴权是新增能力**：在队友加上 Token 前，管理端接口（尤其 `/api/teacher/*`）**没有真实鉴权**；一旦启用 Token，**后端 `allow_headers` 必须加 `Authorization`**，否则预检失败。
3. **响应是裸 JSON**（不是 `{code,data,message}`）；错误体固定为 `{"error":{"code","message"}}`；校验失败统一 422 `VALIDATION_ERROR`。Axios 响应拦截器要按这套解包。
4. **部分接口 `extra="forbid"`**：多传字段直接 422（如 `/api/vision/*`、`/api/healing/*`）。请求体别夹带 UI 字段。
5. **内存态有 TTL**：会话/治愈陪伴 2 小时过期、重启清空——**不要把它当档案存储**；档案/审计必须走新建 SQLite 表。
6. **`history` 只留最近 3 次**：档案页展示「长期趋势」前，需队友放宽该上限。
7. **脱敏要在后端做**：脱敏版报告/概览的敏感字段应由后端按角色不下发，而不是前端「藏」。

## 九、一句话总结

管理端 = **4+1 角色 + 角色/数据范围解耦 + 预警处置闭环 + 脱敏报告 + iCBT 管理 + 审计安全**；前端用 **Vue3 + TS + Pinia + ECharts**，动态路由权限、scope 控范围、组件按业务拆。
**与现有后端的现实差距**：现有只提供「高风险名单 / 个体历史（最近3次）/ 群体聚合 / 跟进备注 / 人工沟通」这一小块，**管理端的其余能力（用户体系、组织花名册、测评任务、量表、预警实体、审计、iCBT、预约、资源、报表、导出）都需要队友新增后端**——建议先把 P0 的 7 项接口清单发给队友确认，再定 MVP 范围。
