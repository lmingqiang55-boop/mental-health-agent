# 对话式抑郁测评契约（第 1 步）

状态：**状态机、规则 Mock、可选结构化模型抽取器、模型决策器与问句生成器已接入；对话方式尚未经效度验证**。本文件规定状态机、模型抽取器、决策器/生成器接口、计分器和验收样例共同遵守的语义；不规定具体模型或提示词。决策器与生成器的分工见第 4 节。

## 1. 测量对象与输出

- 暂定对象：**12～18 岁、能够独立理解问题的中文使用者**。大学生或成年用户应另行选择并核对适用量表版本，不能自动沿用青少年解释标准。
- 核心构念：过去两周的抑郁相关症状频率。基线参照 NIMH 发布的 PHQ-9 modified for Adolescents（下称 PHQ-A）的**前九个计分条目**。
- 第一版输出：九项逐题记录、完整时的 `mapped_total`（0～27）、未完成原因，以及不带额外量表分值的症状画像。`mapped_total` 在产品上标注为“对话式 PHQ-A 条目映射分（研究原型）”。
- PHQ-A 页面另列“过去一年多数日子是否低落”和“日常功能影响”；两者可以单独记录，**不加进九项总分**。页面附带的 ASQ 自杀风险问题属于独立安全流程，也不加进总分。
- 本阶段不输出“抑郁症诊断”“六维临床分数”或个体化治疗处方。若以后加入焦虑、压力、人际关系等数字分数，分别指定工具、题库和验证方案。

**版本锁定点：**开发正式测评前，必须确定使用哪一套经过核对的中文条目原文、作答选项及使用条件，并为其分配 `instrument_version`。本表仅写条目含义，不是经验证中文译文。2024 年一项中国青少年 PHQ-A 适配研究纳入的是 12～18 岁已确诊 MDD 的临床样本；其“缓解”截点不能直接作为普通学生的筛查阈值。不同版本的第 4/5 项排序可能不同，因此程序依赖**稳定的条目 ID 和含义**，不单靠显示顺序。

## 2. 九项与计分规则

所有条目共享同一回顾期：**过去两周**。四档答案：`0=完全没有`、`1=有几天`、`2=超过一半的天数`、`3=几乎每天`。总分只在九项全部确认后计算：`mapped_total = sum(item_01 ... item_09)`。下表序号按 NIMH 页面排列。

| 稳定 ID | 测量内容（非正式译文） | 应区分的情况 |
| --- | --- | --- |
| `item_01` | 情绪低落、易怒或无望 | 青少年可表现为易怒；一时生气不自动计入 |
| `item_02` | 兴趣或愉悦感减退 | 不喜欢某门课不等于对平时喜欢的活动普遍失去兴趣 |
| `item_03` | 入睡、维持睡眠困难或睡得过多 | 单纯作息晚不自动视为睡眠症状 |
| `item_04` | 食欲或进食量变化 | 只谈体重变化而无相应经历，需澄清 |
| `item_05` | 疲倦或精力不足 | “学习任务多”本身不等于疲倦 |
| `item_06` | 自我评价低、失败感或让家人失望感 | 普通的一次考试失利需追问是否形成反复体验 |
| `item_07` | 注意力难以集中 | 可涉及学习、阅读等活动 |
| `item_08` | 他人可察觉的动作/说话变慢，或明显坐立不安 | 不能只凭聊天回复速度推断 |
| `item_09` | 觉得不如死去或想伤害自己 | 同时触发独立安全检查；分值不等于风险分级 |

**回顾期继承：**系统发出明确限定“过去两周”的条目问题后，用户紧接着回答“完全没有／有几天／超过一半／几乎每天”，可以继承该问题的条目和回顾期。脱离当前问题的自由叙述，必须自行包含足够的条目线索与时间信息，或经用户确认后才能计分。

**天数与口语：**“总是、经常、偶尔、最近、十天左右”等词只能生成候选类别，不直接成为已确认分值。即使用户报出具体天数，系统也要请其在四档答案中确认，避免自行发明“几乎每天”的天数阈值。

## 3. 逐题证据状态

每个条目只允许以下状态转移：

```text
unasked → mentioned → needs_clarification → confirmed
    └───────────────────────────────────────→ confirmed（直接给出明确答案）
confirmed → needs_clarification（新回答与旧回答矛盾）
```

`confirmed` 的最低条件：

1. 可定位到该条目的**用户原话**，并记录轮次；模型推测或他人描述不计入。
2. 回顾期是过去两周，或由当前明确的量表问题继承。
3. 用户明确选择了四档频率之一；可由清晰自由回答提出候选，再经追问确认。
4. 否定、引用他人的话、过去事件、假设句和前后矛盾均已处理。
5. 条目与分值由服务端规则确认；生成式模型只能提交候选证据，不直接修改总分。

建议保存的最小记录：

```json
{
  "item_id": "item_03",
  "status": "confirmed",
  "category": "more_than_half_days",
  "score": 2,
  "evidence_quote": "过去两周睡不好，超过一半的天数",
  "evidence_turn_id": 4,
  "period": "past_14_days",
  "confirmed_by_user": true,
  "instrument_version": "phqa_zh_pending",
  "extractor_version": "rule_mock_v1"
}
```

未问过的条目是 `unasked`，不是 0 分。用户主动描述某症状但时间或频率不明时为 `mentioned` 或 `needs_clarification`。新回答与既有确认分值冲突时，保留两段原话，暂停该项计分，追问“以过去两周为准，哪种频率更符合实际？”不得静默覆盖。

## 4. 每轮决策与停止条件

每轮依次执行：`安全信号检查 → 条目证据抽取 → 证据校验/冲突检查 → 更新状态 → 模型选择动作 → 生成问句 → 记录`。

**下一问由模型决策器选择，不由程序排序。** 决策器读取本轮学生原话、抽取到的证据、当前条目、九项的 `asked_once`/`confirmed` 状态和最近对话，输出一个结构化动作：

```json
{
  "target_item_id": "item_03",
  "intent": "clarify_frequency",
  "anchor_quote": "睡不好",
  "reason": "时间窗清楚，但没有落到四档频率"
}
```

`intent` 取五类之一：

| intent | 含义 | 合法性前提 |
| --- | --- | --- |
| `open_topic` | 开启主题 | 该条目尚未被明确问过（`asked_once=false`） |
| `clarify_period` | 澄清时间 | 该条目已问过，时间窗不清 |
| `clarify_frequency` | 澄清频率 | 该条目已问过，未落到四档 |
| `resolve_conflict` | 处理矛盾 | 该条目已记录矛盾，且引用学生原话 |
| `confirm_mention` | 确认主动提及的主题 | 该条目有学生自己的原话证据 |

程序**只校验合法性，不替模型挑主题**：

1. 条目必须存在，且仍在开放集合中（已确认且已问过的条目为关闭，不能无理由重复）；
2. `anchor_quote` 必须真的出现——取自本轮原话或该条目的已记录证据，虚构引用一律拒绝，不做改写代替；
3. `intent` 必须与已记录状态一致（不能"开启"一个已问过的条目，也不能"处理"一个没有记录的矛盾）；
4. 动作非法时**拒绝该轮**，不用另一套规则补一个主题；该轮不提交，可重试。

安全信号仍是程序侧硬约束，优先级高于任何动作：出现当前自伤或轻生相关表述时暂停普通测评，进入安全支持路径。此外没有"结束"动作：只要九项中还有未确认、或未被明确提问的条目，本轮就必须继续提问。

每个被选中的动作写入 `AssessmentSession.action_log`（条目、intent、引用原话、理由、决策器版本、最终问句、轮次），作为后续用真实对话数据训练或替换决策模型的状态—动作—问句记录。

只有九项均为 `confirmed`，且没有待处理的分值冲突时，`status=complete`，`mapped_total` 才是整数。其他情况一律 `mapped_total=null`，展示已确认项和待补项。若用户选择停止，保留部分记录，状态为 `stopped`，不补零、不按比例换算。

## 5. 安全处理与结果措辞

- `item_09 > 0` 或自由对话出现自伤相关表述时，记录独立 `safety_flag=needs_review`，进入进一步安全评估流程；**不能把 item_09 分值直接当作即时危险等级**。
- 用户表达当前实施意图、计划或正在发生的危险时，`safety_flag=urgent`，普通测评暂停，并提示立即联系身边可信任的人、当地急救或专业人员。实际分级和后续处置规则须由负责的临床人员审定。
- 当前演示版尚无人工安全评估入口，所以 `needs_review` 也暂停普通测评；会话不能通过继续聊天自动解除暂停。关键词 Mock 只用于流程联调，不承担真实风险分级。
- 未出现相关表述只表示“本轮未观察到信号”，不表示风险为零。安全状态与量表总分分别存储。
- 报告只描述“症状频率／筛查结果”和适当的求助建议；确诊、处方与具体治疗选择由专业人员完成。

## 6. 人工可核对的验收样例

样例中的提问均假设已指向表中所列条目；“待确认”意味着程序不得提前写入最终分值。

| 当前目标 | 用户回答 | 期望状态与下一步 |
| --- | --- | --- |
| `item_03`，问题已限定过去两周 | “完全没有睡眠问题。” | `item_03=0`，保留原话，继续其他条目 |
| `item_03`，问题已限定过去两周 | “超过一半的天数睡不好。” | `item_03=2`，继续其他条目 |
| `item_03` | “最近总睡不好。” | `needs_clarification`；追问过去两周属于四档中的哪一档 |
| `item_03` | “这两周大约十天睡不好。” | 候选为较高频率，**待用户选档确认**，不能直接写入 2 或 3 分 |
| `item_02` | “我不喜欢数学课。” | 不足以判定兴趣减退；继续询问平时喜欢的活动 |
| `item_01`，用户主动谈近况 | “这两周几乎每天心情低落，睡眠也不好。” | `item_01` 可确认 3 分；`item_03` 只记线索，下一问澄清睡眠频率 |
| `item_05`，问题已限定过去两周 | “没有，我精神还可以。” | `item_05=0`；否定要绑定到当前条目 |
| `item_07` | “去年备考时很难集中。” | 不计入过去两周，追问当前情况 |
| `item_03` | “昨天说没问题，但其实这两周几乎每天失眠。” | 保留两次原话，标记矛盾，确认后再更新分值 |
| 任意条目 | “我现在想伤害自己。” | 暂停普通测评，进入安全支持；不借此给其余条目打分 |
| 九项中只确认八项 | “先到这里吧。” | `status=stopped`、`mapped_total=null`、待补项数量为 1 |
| 九项均明确确认 | “这些答案都确认。” | `status=complete`；服务端将九项相加，范围必须为 0～27 |

## 7. 本步骤的验收条件

- 产品、后端和人工标注员对同一回答使用上述同一套条目状态与四档频率。
- 每个非空分值都有用户原话、条目 ID、回顾期和轮次；缺项、口语频率、冲突均不会生成完整总分。
- 同一状态注入不同的模型动作，必须产生不同的合法下一问；程序不得用固定顺序改写模型选定的主题或意图。
- 非法主题、虚构引用、与状态不符的 `intent` 一律拒绝，且该轮不提交；不得用另一套规则补一个主题。
- 九项中只要有未确认或未被明确提问的条目，`status` 不得为 `complete`，`mapped_total` 必须为 `null`。
- `item_09` 的安全流程独立于量表计分；“高总分”不替代自伤风险评估。
- 报告将正式量表条目、功能影响和其他背景信息分开，未验证的六维画像不伪装成六个量表分数。
