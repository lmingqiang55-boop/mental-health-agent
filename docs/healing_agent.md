## 运行与代码入口

使用项目的 `mental-health-agent` Conda 环境及本地 `.env`，按 README 启动后端。
新依赖为 `jieba`、`rank-bm25` 和 `beautifulsoup4`，版本已写入 `requirements.txt`。
治愈模块共用现有 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`，通过兼容 Chat Completions 的客户端生成 JSON。
评估模块的 `DEEPSEEK_API_STYLE` 和 `DEEPSEEK_STRUCTURED_OUTPUT` 继续独立控制评估请求。

## POST /api/healing/start

首次进入前，必须存在当前匿名学生的至少一条实际评估记录。
采用该学生最新可读取的记录，绑定其 `result_id`；记录可以来自同一匿名学生的较早会话。

```json
{
  "session_id": "当前会话标识",
  "request_id": "客户端生成的唯一操作标识",
  "regenerate": false,
  "background": {
    "current_concern": "明天考试，想到考不好就很紧张"
  }
}
```

`session_id`、`request_id` 必填；其余字段可以省略。`background.age` 不再是请求字段，传入时返回 422；无需增加显式年龄接口。
数值年龄统一取自本轮绑定的最新评估记录 `result.age`。年级保留在 `assessment.grade`，常见小学一至六年级、初一至初三/七至九年级、高一至高三映射为 `primary`、`middle`、`high`。未知年级不猜学段；没有可映射年级时，仍可用明确取得的可选 `background.school_stage`，有已识别年级时以记忆为准。
最新记录缺少年龄时保持未知，不从年级推算，也不沿用旧评估的年龄。当前陪伴支持 6–18 岁；记忆年龄超出范围或与最终学段明显冲突返回 422 `VALIDATION_ERROR`，已有陪伴状态保留。缺失背景不能使用前端默认学段或假资料补齐。
`background.adult_support_available` 可以省略，或传入明确取得的 `true` / `false`。首次进入时也可复用当前筛查文字、具体困扰或限制中明确的当前成人支持表述；仅有“我有父母”不表示有人愿意且能够陪伴。
没有确认成人支持时，只有实际选中了需要成人指导的方法才询问：“你身边有没有一位你信任、愿意也能陪你试试的大人？”对应方法暂不展示步骤，也不计为活跃建议；不需要成人的方法可直接展示。
学生通过原来的聊天接口回答。紧接本问题的“有”可启用符合其他条件的方法；“没有”排除成人方法，“不确定”或不愿回答保持未知，本轮不重复追问，继续陪伴并可选择自主方法。后来明确说明成人能够或不能陪伴时，按最新条件重新筛选，即使之前上游传了相反值。确认成人可用仍保留知识来源的成人及其他前提，不意味着成人已经在场或方法已经尝试。
成人支持状态仅随当前陪伴保存在进程内，不写回持久评估记忆；公开请求和响应协议保持原样。
背景还接受 `important_events`、`preferences`、`constraints`、`previous_attempts`，均为明确取得的信息组成的字符串数组，每项最多 500 字、每组最多 10 项。

已有陪伴状态且 `regenerate=false` 时恢复当前报告、历史和反馈，背景改动不会偷偷重生成。
主动重生成须携带 `regenerate=true` 和当前 `expected_healing_id`，并使用新的 `request_id`。
成功后绑定最新可读取评估、建立新一轮；失败保留原绑定和进度，最新安全信号仍会触发求助分流。出现新评估记录不会自动替换旧陪伴的绑定。
同一操作在请求未确认时重试，必须复用原 ID 和完整原请求。已用于其他内容的 ID 返回 409。

## GET /api/healing/{session_id}

读取可用的当前陪伴状态，不生成新报告。不存在或过期返回 404，并明确提示重新进入。
读取、恢复和幂等重试会同步当前筛查风险、危机模式及用户文本；需要分流时返回 `referred`，停用方法、隐藏报告建议和追问。保留原评估绑定、轮次及反馈，重复读取不追加相同求助提示。生成完成后的提交也进行同样检查，迟到的普通回复及其反馈不会覆盖新风险。此机制不主动推送已经返回响应之后发生的风险变化。
前端离开陪伴区域后返回，可先调用此接口；返回成功后恢复原报告和进度。
不要求页面刷新、新建会话或服务重启后恢复旧历史。

## POST /api/healing/chat

```json
{
  "session_id": "当前会话标识",
  "healing_id": "进入接口返回的陪伴标识",
  "message_id": "客户端生成的本次回答标识",
  "text": "第一个方法我试了，但没有帮助"
}
```

回答最多 4000 字，不接受空白。重试复用相同 `message_id` 和文本，避免重复写入反馈或并行生成。
同一 ID 改内容、使用重生成前的旧 `healing_id` 或超过保存上限，均返回 409。没有新风险分流时，已经结束的本轮也返回409；当前会话出现新安全信号时先切换求助状态。
幂等重试返回当前状态，不会把页面回退到较早轮次。

成人支持确认也使用上述接口和幂等规则，不需要新的表单或接口。只有对应提问后的短回答才解释为成人条件，其他语境的“有/没有”不会更新成人状态；条件回答不会记录成准备、尝试或效果反馈。回答后，读取与恢复返回的报告问题同步更新，不继续显示已回答的成人问题。模型生成失败时仍保留原状态，可复用相同消息ID重试。

学生明确准备某个方法时，按首次展示的固定编号或完整标题关联，停用、恢复、简化及后续新增方法不会重排旧编号。新增方法在助手消息中明确标注“第N个方法”；内部display_number不进入公开响应字段。历史快照只包含部分方法时仍保留各自的编号。明确共同准备且所指的两条清楚时可记录两条；新旧方法指向不清时澄清或暂停，不猜测归属。否定、无效或同轮被条件停用的方法不误记准备；准备与实际尝试分别保留，重试不重复写入反馈。

只有明确反馈才更新尝试及效果。`还没试`、`准备试试`、`试了但没用` 分别对应未尝试、准备、尝试且无效。
多个方法且反馈指向不清楚时使用一个问题澄清；不会默认全部无效。
同轮分别反馈两个方法时，每条引用按原回答中的局部序号或标题核对，不用整段回答的第一个序号或其他位置出现的标题代替关联。建议顺序固定为回答前的快照；同轮过滤及前一条反馈停用方法不会重排后续反馈的序号。跨越不同方法或重复出现在不同方法上下文中的含糊引用不记载；明确共同反馈可以分别关联到两个方法。
明确不愿采用或无效的建议保留原关联和反馈，后续按稳定 `method_key` 排除，避免更换编号后重复推荐。
暂停状态可以继续发送；结束状态需主动重新生成一轮。普通回答每轮最多一个主要问题，暂停和收尾可以没有问题。纯暂停或准备仍可无需模型处理；带明确效果或拒绝反馈时先完成反馈校验再暂停，包括此前已确认尝试、当前只补充效果的回答。“不要先暂停”等明确否定或后续撤回不触发程序暂停，明确否定暂停也优先于准备状态的自动暂停。

## 三个接口的响应

```json
{
  "session_id": "当前会话标识",
  "healing_id": "当前陪伴标识",
  "assessment_result_id": "本轮绑定的实际评估标识",
  "status": "active",
  "turn_count": 0,
  "report": {
    "understanding": "对实际经历和感受的简短回应",
    "focus": "本轮关注方向",
    "suggestions": [{
      "title": "方法标题",
      "goal": "方法目标",
      "steps": ["经知识校验的步骤"],
      "prerequisites": ["必要成人或其他前提"],
      "cautions": [],
      "execution": "unconfirmed",
      "effect": "unknown",
      "active": true
    }],
    "cautions": [],
    "question": "一个主要问题",
    "generated_at": "ISO 8601 时间"
  },
  "messages": [],
  "risk": {
    "risk_level": "low",
    "risk_score": 0.1,
    "risk_reasons": [],
    "risk_types": [],
    "key_evidence": [],
    "requires_intervention": false
  },
  "notice": "本次陪伴记录仅在当前会话中保留；刷新或服务重启后请重新进入。"
}
```

状态为 `active`、`paused`、`ended` 或 `referred`。
`messages` 为独立的陪伴历史，每项包含 `role`、`content` 和 `created_at`；首次报告不重复塞进历史。
建议执行状态还包括 `not_attempted`、`prepared`、`attempted`、`declined`，效果为 `unknown`、`helpful`、`ineffective`、`worse`。
已表示准备后明确“还没试”，建议保留 `prepared`，另记本轮 `not_attempted/unknown` 反馈；这是保留意愿与记录事实，不认定已经尝试。实际尝试或明确拒绝仍更新原状态。反馈及内部更新建议保持 `persisted=false`。
建议 `active=false` 时前端应显示已反馈并调整，避免继续把原步骤呈现为当前应做的事。
暂停、结束或转入求助时，报告中的问题为 null；新建议和动态问题见最新助手消息，原始报告继续保留。
危机或需要现实求助时 `referred`，隐藏旧方法和问题，采用已有求助话术；不自动给老师或家长发消息。

学生响应不包含知识 ID、来源网址、引用、内部建议 ID 或检索分数。
内部 `HealingState` 保留来源版本、摘要、原文位置、适用过滤结果、建议关联、反馈及耗时审计。
`memory_update_suggestions` 只作为内部更新提议，`persisted=false`；目前没有老师端审计接口或跨会话反馈写入接口。

## 前端接入约定

1. 评估成功仍按原流程展示和入库，由学生点击独立入口才调用 `/start`。
2. 陪伴模式的新回答发送 `/healing/chat`；音频可沿用现有转写后发送文字。
3. 筛查报告和陪伴报告分别保留；陪伴回答不调用 `/chat` 或 `/assessment`，不清空筛查结果。
4. 返回筛查时保留原对话；需要新筛查时显式创建新会话，避免把陪伴消息评估成原筛查输入。
5. 生成和发送期间禁止重复操作；网络结果不明时保存原请求用于重试，503 时可重试或保留旧陪伴。
6. 404 明确引导重新进入或新建会话；409 提示状态已变化后读取当前陪伴；不要假装恢复丢失的旧反馈。

## 错误与保存期限

错误格式沿用 `{ "error": { "code": "...", "message": "..." } }`。

| HTTP | code | 含义 |
| --- | --- | --- |
| 404 | `HEALING_SESSION_EXPIRED` | 原会话不可用，需新建会话 |
| 404 | `HEALING_NOT_FOUND` | 陪伴状态不可读，需重新进入 |
| 409 | `HEALING_ASSESSMENT_REQUIRED` | 当前匿名学生没有评估记录 |
| 409 | `HEALING_REQUEST_CONFLICT` | 幂等标识被用于不同输入 |
| 409 | `HEALING_STATE_CHANGED` | 当前陪伴标识已变化 |
| 409 | `HEALING_ENDED` / `HEALING_TURN_LIMIT` | 本轮结束或达到 80 轮保存上限 |
| 422 | `VALIDATION_ERROR` | 字段、背景、文本或记忆中的年龄/学段不合格 |
| 503 | `HEALING_UNAVAILABLE` / `HEALING_BUSY` | 模型、格式或依据检查失败，或服务繁忙 |

陪伴使用逐会话异步锁；同一会话串行，不以一把全局锁等待所有模型请求。
仅完整成功结果写回，新请求失败不会留下半轮消息或误记尝试。
陪伴最多保存 1000 个会话，空闲 TTL 为 2 小时；还受原 Session 的独立 2 小时时限约束。
单进程运行；多 worker 的状态共享和跨会话持久化不属于这一版。

## 优先方向、表达及安全门控

同时出现两个以上明确困扰、没有表明优先方向时，首次报告先保留一个确认问题，不生成方法。明确‘先聊考试’后生成正式报告；普通提及晚睡不会自动切换，明确‘换成睡眠’会切换目标并停用旧目标的方法。交流策略按明确年龄分为 6–10、11–13、14–18；年龄未知但学段已知时仅按学段选择表达，不补数值年龄或放宽来源范围。

进入前的限制、偏好和无效尝试在硬过滤后做有依据的适配检查；必要条件不明时保持未知。最新限制能停用已提出的方法，不能凭此编造‘已经试过’。纯粹指向原方法的无效反馈由原关联处理，不拿来过滤未推荐的候选；已确认尝试后，后续单独说‘没有帮助’可以记录效果。最多保留两个活跃方法。

方法有已独立校验的完整简短表达时，学生明确说文字难懂且指向清楚，可保持建议 ID、知识 ID、成人条件和反馈，换用简短表达并记录修订。未通过的表达、含义不清或已经无效的方法不能借‘简化’重新推荐。连续简短无信息同义回答允许暂停；已暂停时再说不清楚/不知道说什么，使用短收尾，不重复此前整段内容，不重置或杜撰进度。已有simple仍要求继续缩短按用户确认略过，不新增更短版本或删条件，不计为通过。

适配层在 Pydantic 填默认值前检查持久记录原始 risk 字段。新保存记录增加 `risk_input_fields`，记录实际提供的风险字段；只是 `RiskResult()` 的默认值不能当作已完成低风险确认。旧记录若已把完整默认值序列化且没有来源标记，无法追溯区分默认值与真实提供值，这个历史限制仍存在。缺失/冲突风险先暂停方法，使用‘需要确认，不代表已经判定危机’的表达；明确行动计划、严重功能受损、持续恶化或欺凌威胁按求助路径处理。

模型自由文字做程序和独立语义检查。一次修复后仍不合格，可改用不增加个人事实的固定回应和单问题，再独立检查；受限问题仍被拒绝时可无问题暂停并再次独立核对；程序追加必要方法澄清也走该检查路径。方法仍只从已有合格候选呈现，反馈仍执行原话和关联门控。未知知识编号、错误关联、连接超时等仍返回 503，保留原状态。审计记录文字降级；不能把求助建议说成已完成联系或通知。
