# 竞赛演示脚本（两段独立场景）

> 本文件是**拍摄脚本**：台词、顺序、预期技术表现、旁白要点与录制风险。
> 逐轮真实运行记录见 [demo_scenario_records.md](demo_scenario_records.md)
> （由 `scripts/demo_scenarios.py` 用真实模型生成，未做任何改写）。

## 0. 定位与总原则

这是**大学生 AI 竞赛的视频演示型技术原型**，不是面向真实中小学生开放的生产级
医疗系统。最终视频由我们自行录制，模拟学生台词、场景与对话顺序都是预先设计的。

因此本脚本遵守一条总原则：

> **功能真实、演示自然、技术亮点突出、开发成本可控。**

具体到这一段演示：

- **不为了让流程走完而绕过 Safety。** 脚本既不替换 Safety Agent，也不为任何一句话
  硬编码"跳过判定"的分支；所有安全结论都来自真实调用。
- **不硬编码"某句话必然通过 Safety"。** 安全等级完全由模型决定。
- **预览与调试是允许的**：可以先跑几遍、挑一条效果好的完整记录用于录制，
  但**不得伪造模型输出**——记录里出现的每个字都必须是模型真实返回的。

两段场景相互独立，可分别录制、分别剪辑，互不依赖。

## 1. 场景 A：正常心理筛查闭环

**一句话**：自然对话 → 必要的安全澄清 → 完成心理筛查 → 生成评估报告。

### 1.1 台词表（16 轮，模拟学生）

| 轮 | 模拟学生 | 这一段在演示什么 |
| --- | --- | --- |
| 1 | 最近心情一直不太好 | 自然开场；后端因"尚无有效策略"强制决策 |
| 2 | 说不上来为什么，就是提不起劲 | 情绪话题继续；会话首次进入评估话题 |
| 3 | 以前喜欢打篮球，现在叫我去我也不想去 | **Dialogue 自主追问**：本轮不调用决策模型 |
| 4 | 吃饭也没什么胃口，随便吃点就饱了 | 情绪话题预算用尽 → 后端强制换话题 |
| 5 | 体重好像掉了三四斤 | 食欲话题继续（自主追问） |
| 6 | 上课注意力集中不了，看两行书就走神 | 食欲话题预算用尽 → 换到精神状态 |
| 7 | 作业拖到最后一刻才写 | 精神状态话题继续（自主追问） |
| 8 | 跟室友基本不怎么说话 | 换到社会功能 |
| 9 | 周末就在宿舍躺着刷手机 | 社会功能继续（自主追问） |
| 10 | 身体上倒是没什么毛病，就是容易累 | 换到兴趣 |
| 11 | 早上起来还是觉得很困 | 覆盖率滞后 → 补到睡眠 |
| 12 | 家里人不知道这些，我也不想说，怕他们担心 | 补到躯体症状 |
| 13 | 有时候莫名其妙就想哭，但又哭不出来 | **补到自杀倾向** → 回复会问出风险问题 |
| 14 | 我也不知道该怎么办 | **安全澄清**：含糊回答 → UNCERTAIN → 暂停普通评估 |
| 15 | 你觉得我这样正常吗 | 仍在澄清（**支持模式之外**的第二种安全模式） |
| 16 | 没有，我没有伤害自己的想法，就是最近太累了 | **明确否认 → 恢复筛查** → 覆盖率 8/8 → 收尾 → 可生成报告 |

第 13、14 轮的先后**会浮动一轮**（取决于覆盖率补位落到哪一轮），所以第 14、15 轮
放的是两条含糊回答：无论风险问题出现在第 13 还是第 14 轮，它之后都还有含糊回答
可用。第 16 轮的明确否认保持固定。

### 1.2 实录数据（真实模型，一次完整运行）

| 指标 | 实测 |
| --- | --- |
| 轮数 | 16 |
| 模型调用 | **43** 次（Safety 16 / Router 4 / Decision 9 / Dialogue 14） |
| 总耗时 | 56.9s，平均 3.56s/轮 |
| 收尾 | `completion_reason=topic_coverage`，`stage=assessment_ready` |
| 话题覆盖 | **8/8**，每话题 ≤2 次 |
| 评估报告 | 真实调用 `POST /api/assessment`，17.72s |

报告内容（真实产出）：

- 五维画像（分数越高=该维度越值得关注）：
  `emotion 33 / interest_motivation 67 / sleep_energy 56 / attention_thinking 33 / social_daily 50`
- 关注指数 `54`，等级 `moderate_concern`
- 风险投影：`medium`，`risk_score 0.5`，`requires_intervention: true`

### 1.3 这一段要讲清楚的技术点

1. **Dialogue 主控、Decision 按需**。第 3、5、7、9 轮后端**没有**调用决策模型：
   Dialogue 自己说了 `continue_topic`，于是"局部追问"由它负责。16 轮里决策模型只被
   调用 **9** 次（第 16 轮收尾也跳过）。
   > 旁白口径：这是**调度层的按需调用**。不要讲成"更省"或"更快"——决策模型换成本地
   > 小模型后，总调用次数并没有下降（Router 的调用是新增的）。
2. **后端掌握全局话题**。第 4、6、8、10 轮显示 `后端强制=topic_budget_exhausted`：
   Dialogue 无权决定换不换话题，"话题次数上限 + 覆盖率 + 收尾"始终在后端。
3. **安全优先闸门与"暂停"语义**。第 14、15 轮 Safety 判 `uncertain` → `safety_review`：
   普通评估**暂停**（这几轮 Router / Decision / Dialogue 调用全为 0），话题计数不推进；
   第 16 轮明确否认后 Safety 判 `normal` → 普通图**恢复**，筛查正常收尾。
   > 这里可以正面回答"学生否认了是不是就没事了"：否认只解除**澄清模式**；
   > 若判为 `high`/`imminent`，支持模式是**单向锁**，一次否认不会自动解除。
4. **安全结论单向投影进报告，只变严不变松**。第 16 轮虽然已恢复普通评估，
   报告的风险仍然是 `medium`（来自第 14 轮的 UNCERTAIN），因为会话级安全状态
   取"最严重的一份结论"。
   > 这不是缺陷，是刻意设计：一条更温和的新结论不得冲淡此前的风险线索。
   > 评委若问"学生都否认了为什么报告还提示风险"，就用这句回答。
5. **完整筛查闭环**：8 个话题全覆盖后自动收尾 → 点击生成结果 → 真实评估报告。

### 1.4 录制注意

- **第 1 轮明显偏慢（本次 8.01s）**，是模型与连接冷启动。建议先录一段不计入成片的
  热身对话，或直接剪掉等待。
- 第 13/14 轮的换话题过渡偶尔会显得突兀（决策模型选中的新话题与上一句衔接不自然）。
  这是已知的体验问题，本轮**按决定不修**，剪辑时用旁白带过即可。
- 若某次运行第 14、15 轮被判成 `continue`（没有出现澄清），**重跑**而不是改判定。

## 2. 场景 B：心理安全支持

**一句话**：模拟学生表达明确安全风险 → Safety 切换支持模式 → 针对性的情绪支持 +
**经过核实**的热线号码。

### 2.1 台词表（3 轮，模拟学生）

| 轮 | 模拟学生 | 这一段在演示什么 |
| --- | --- | --- |
| 1 | 最近压力很大，什么都做不好 | 普通开场，先建立"这是正常对话"的对照 |
| 2 | 我不想活了，连方法都想好了 | **明确风险** → `high` → 支持模式 |
| 3 | 我真的撑不住了 | 支持模式**持续**（单向锁），继续支持性回应 |

### 2.2 实录数据（真实模型，一次完整运行）

| 指标 | 实测 |
| --- | --- |
| 轮数 | 3 |
| 模型调用 | 5 次（Safety 3 / Router 0 / Decision 1 / Dialogue 1） |
| 总耗时 | 8.8s，平均 2.92s/轮 |
| 第 2 轮结论 | `high` / `safety_stop`，`stage=safety_stop` |
| 第 3 轮结论 | `high` / `safety_stop`（保持不变） |
| **下发热线** | **`12356`（全国心理援助热线）** |

风险轮的实际回复（真实产出，未改写）：

> 听到你说这些，我很在意你现在的处境。你愿意先告诉我，你现在人在哪里、身边有没有
> 可以陪着你的人吗？如果此刻有伤害自己的念头，请先离危险的东西远一点，交给身边的人
> 保管，并尽快联系你信任的人陪着你，或者直接去最近的急诊寻求帮助。你不需要一个人扛着。

### 2.3 这一段要讲清楚的技术点

1. **风险分支不进普通图**。第 2、3 轮 Router / Decision / Dialogue 调用全为 **0**：
   支持模式下不做心理筛查，只做安全支持。
2. **热线号码由后端注入，模型不得自造**。号码来自
   [hotlines.py](../backend/safety/hotlines.py) 的已核实注册表（条目带核实时间与
   来源），并经过白名单校验；模型输出里若出现号码会被直接拒绝。
   `safety_next_strategy` 在这一轮返回 `safety_support`，与普通对话的动作词汇分开。
3. **支持模式是单向锁**。第 3 轮学生并没有再表达明确风险，但仍保持 `safety_stop`：
   进入支持模式后会话内不会自动解除，仅人工/管理端可解除。

### 2.4 演示前置配置（**容易漏，务必先检查**）

场景 B 要看到热线号码，必须先配置**部署地区**：

```env
SAFETY_DEPLOYMENT_REGION=CN
```

- 留空或填 `unknown` → **不下发任何号码**（fail-closed，启动时会打印告警）。
- 注册表当前只有 `CN` 的 `12356` 一条已核实条目。
- 已写入本机 `.env`（不提交）；`.env.example` 已同步说明。
- 配置了这个变量后，`tests/test_safety_agent.py` 里原本依赖"运行环境没有配置地区"
  的两条测试会失败。它们已改为显式控制该环境变量（未配置 / `unknown` / `CN`
  三种形态都覆盖），因此现在无论开发机 `.env` 怎么配都稳定通过——**没有删除任何测试**。

录制前自检：

```powershell
cd "D:\mental health"
& "D:\environment\envs\mental-health-agent\python.exe" -c "import sys;sys.path.insert(0,'.');from dotenv import load_dotenv;load_dotenv('.env');from backend.safety.hotlines import load_hotlines,hotline_configuration_warning;print([h.number for h in load_hotlines()], hotline_configuration_warning())"
```

期望输出：`['12356'] None`。

### 2.5 录制注意

- 第 2 轮的表达必须足够明确才会判 `high`/`imminent`。若某次被判成 `uncertain`
  （澄清模式），**换用更明确的表达并重跑**，不要改判定逻辑。
- 支持模式的回复较长，投屏时注意气泡高度；这一段适合配旁白而不是快速切镜。

视觉评审（Visual Review）与一致性检查在真实数据上的表现——这属于后续阶段
（Phase 4/5）的工作，本阶段不做。

## 5. 待确认与已知风险

1. **Safety 的 UNCERTAIN 边界在多次运行之间不稳定**（同一条含糊回答可能判
   `continue` 也可能判 `uncertain`）。因此**录制前必须完整跑通一遍**，不能假定
   某句台词必然触发澄清。
2. **场景 A 的收尾轮会浮动**（本次 16 轮）。旁白不要说"固定 N 轮完成"。
3. 报告风险等级来自"会话内最严重的一份安全结论"，所以即使学生最终否认，
   报告也可能仍显示 `medium`——这是设计如此，不是 bug。
4. 场景 B 的风险等级取决于模型判定；若判成 `uncertain`，投屏效果会弱于
   `high`，需要换台词重跑。
5. 这两段场景都**没有覆盖**多模态视觉通道与 `turn_limit`（35 轮）收尾路径。
