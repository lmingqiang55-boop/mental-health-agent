# 语音识别实现与验证记录

日期：2026-10-02。后端实现与现有聊天、评估已对接；前端按钮录音页面和视觉
区间聚合按规划交给相关队员。本记录区分自动化验证、真实模型实测与尚待验收
的行为，接口和运行方法见 [语音接入说明](speech_recognition.md)。

## 模型决定

本轮保留 **FunASR + SenseVoiceSmall**，新增 **faster-whisper Small** 对照脚本。
相同的合成录音中，两种模型都保留了“没有”、睡眠表述和关键否定词；
Whisper 没有解决单字“嗯”的识别问题，预热后耗时更长。当前数据支持继续使用
SenseVoice 整段方案。随后一份真人“嗯”录音在两种模型上均通过，见下文补测；
尚不足以宣称所有真实麦克风场景的识别质量已经验收。
后续真人五句补测中，SenseVoice 保留了全部单句词语，Whisper Small 将单句
“睡不着”识别为“睡补着”；这一实测也支持保留当前生产模型。

Whisper 的构造与预热较快，部分样本标点更稳定，但没有显示足以更换生产路径
的识别收益。本轮只比较 small、固定中文、无 VAD 配置，不代表整个 Whisper
模型系列的质量上限。未来若更多真人短应答未达标，再比较更大模型、其他模型或
采集改善；不把“文”等输出直接映射成“嗯”，避免改写真实话语。

## 环境与模型版本

- Windows，Miniforge `mental-health-agent` 环境。
- CPU：AMD Ryzen 7 7745HX；GPU：NVIDIA GeForce RTX 4070 Laptop GPU，8 GB。
- 生产依赖：torch / torchaudio 2.8.0+cu128、FunASR 1.4.16、ModelScope 1.40.1、
  PyAV 18.1.0、SentencePiece 0.2.2、NumPy 2.4.6。
- SenseVoice：ModelScope `iic/SenseVoiceSmall`，revision `master`；因分支可变，
  此次 `model.pt` 的 SHA-256 为
  `833ca2dcfdf8ec91bd4f31cfac36d6124e0c459074d5e909aec9cabe6204a3ea`。
- 对照依赖：faster-whisper 1.2.1、CTranslate2 4.8.2。
- 对照权重：`Systran/faster-whisper-small`，revision
  `536b0662742c02347bc0e980a01041f333bce120`。
- SenseVoice 使用内置模型实现与 `trust_remote_code=False`。实测修复了
  SentencePiece 在 Windows 中文缓存路径中的文件读取问题，使用 Python 读取
  模型字节，无需修改第三方安装包或移动缓存。

上述依赖已在指定环境安装，`pip check` 通过。权重和测试录音不提交仓库；
启动仍需在本地 `.env` 启用 `ASR_PROVIDER=sensevoice`，GPU 用 `ASR_DEVICE=cuda:0`。
默认关闭 ASR，原有文字服务可以独立启动。首次下载和缓存准备见接入说明。

## 预热后的耗时对照

测量口径：完整文件在内存中解码为 16 kHz 单声道，执行整段识别并取到全部
文本；表中为“解码 + 推理”毫秒中位数。两种模型都指定 `zh`，CPU 线程为 4；
SenseVoice GPU 使用 torch，Whisper GPU 为 float16、CPU 为 int8，beam size 5，
temperature 0，关闭 VAD 和前段文本条件。SenseVoice GPU 每条测 5 次，其余
每条 3 次；属于本机小样本基准，有运行波动。

| 录音时长 | SenseVoice GPU | Whisper Small GPU | SenseVoice CPU | Whisper Small CPU |
| --- | ---: | ---: | ---: | ---: |
| 3 秒 | 99.93 ms | 346.61 ms | 229.55 ms | 1172.92 ms |
| 10 秒 | 369.90 ms | 674.92 ms | 529.10 ms | 1765.70 ms |
| 30 秒 | 1039.16 ms | 2269.69 ms | 1596.82 ms | 4840.66 ms |

3 秒样本为“没有”加静音；10 秒为睡眠表述和“没有”；30 秒为学习压力、否定
伤害自己及睡眠表述的多句话录音，含停顿和少量尾部静音。长度通过真实波形
构造，整段输入，不靠截断录音获得耗时。三组均保留完整内容，SenseVoice
30 秒样本有标点变化及偶发重复句号，后端按约定不进一步润色。

SenseVoice 默认 `auto` 的 CPU 补测中位数为 258.70 / 563.84 / 1450.16 ms。
新进程中、权重已缓存的模型加载与预热：SenseVoice GPU 约 14.75 秒，CPU
约 13.81 秒；真实 ASR 应用启动探针约 14.62 秒。Whisper 构造与预热为 GPU
约 1.92 秒、CPU 约 1.85 秒，该脚本的这项统计不含预先读取模型文件为字节的
时间，不能直接当作完整进程冷启动比较。Whisper 首次下载及缓存查找约 61.57
秒；未单独测量 SenseVoice 首次网络下载时间。

这些数字不含远程网络上传、视觉汇合或策略模型回复，不能当作“松开到最终
回复”的耗时承诺。短录音本地计算已在 1～2 秒目标内，完整页面等待仍需联调。

## 识别内容核对

主要样本由 Windows 中文 TTS 合成，内容为虚构测试表述。核对原词和否定语义，
没有计算大规模字错误率，也没有用 LLM 修正识别结果。

| 输入 | SenseVoice | faster-whisper Small | 判断 |
| --- | --- | --- | --- |
| “没有” | “没有。” | “没有” | 本样本通过 |
| “我不想自杀，我只是有点难过。” | 保留完整否定句 | “我不想自殺,我只是有點難過。” | 否定词保留；Whisper 出现繁体 |
| 夜间睡不着、凌晨醒后难入睡 | 完整保留 | 完整保留 | 本样本通过 |
| 多句话，含“没有想过伤害自己”“没有失去兴趣” | 完整保留，有标点波动 | 完整保留 | 不拆聊天回合 |
| “这几天睡眠不好，不过我没有不想吃饭。” | 保留“没有不想吃饭”及尾字 | 同样保留 | 本样本通过 |
| 单字“嗯”，Huihui 声音 | 固定中文为“文。”；auto 曾为“lan.”或仅句号 | “阿伦” | 未通过 |
| 单字“嗯”，Kangkang / Yaoyao 声音 | “文。” | “文” | 未通过 |
| “嗯，没有。” | “文没有。”或“文，没有。” | “文 沒有” | 未通过“嗯” |
| “没有想过。” | 正确 | “沒有想過” | 语义保留 |

三种合成声音的“嗯”都失败，无法据此区分发音合成问题和真实短应答能力；
更换到本轮 Whisper 配置不能解决。合成结果不得宣传为真人准确率。繁简兼容
也应在未来更换模型时单独验证，不能假设现有风险关键词覆盖全部书写形式。
模型目录附带的中文示例音频识别为“开放时间早上9点至下午5点。”，仅作为
额外冒烟样本，不作为项目场景验收。

## 真人“嗯”录音补测

用户随后提供一份本人录制的单字“嗯”音频：M4A / AAC、48 kHz、双声道，
78410 B，按生产解码器重采样后的完整时长为 3029.31 ms。直接使用完整原文件，
不裁剪、不补静音、不用已知答案作为提示，也不改写转写文本。

在同一 GPU 和已缓存模型上，每种配置对同一文件重复推理 5 次：

| 模型与语言配置 | 5 次输出 | 解码 + 推理中位耗时 | 耗时范围 |
| --- | --- | ---: | ---: |
| SenseVoice，默认 `auto` | 全部为“嗯。” | 75.65 ms | 73.13～78.99 ms |
| SenseVoice，固定 `zh` | 全部为“嗯。” | 95.86 ms | 89.62～105.40 ms |
| faster-whisper Small，固定 `zh` | 全部为“嗯” | 201.47 ms | 192.12～262.48 ms |

这份真人录音通过，两种模型的输出均可作为非空聊天文本；标点差异不影响
词语内容。此结果表明此前合成样本的失败不能直接推出模型无法识别真人“嗯”，
支持继续保留 SenseVoice。重复推理验证的是同一文件的结果稳定性，并非 5 位
说话人或 5 份独立录音的准确率；其他短应答、发音和噪声条件仍需测试。
此补测未涉及前端按钮、实际采集时间轴、视觉聚合或策略回复。原始真人录音
不纳入代码仓库，仅在本文记录匿名测试结果。

## 真人五句与五合一补测

用户按本次对话提供的 5 句虚构测试文本录音，另录制一份五合一。目录中还有
上一节单字“嗯”的两个相同副本；按内容哈希仅重复测试其中一份，不删除文件。
全部为 AAC、48 kHz、双声道，使用完整原文件解码与真实重采样，不裁剪。

SenseVoice 分别用 `auto` 和 `zh`，Whisper Small 用 `zh`，每份文件在每种
配置下重复 3 次。对 5 条单句，SenseVoice 两种语言配置每次均保留了全部
词语和关键否定词。下表耗时为 GPU 预热后的“解码 + 推理”中位数，不含模型
加载、网络上传、视觉准备或策略回复。

| 编号与录音文件 | 时长 | SenseVoice auto | SenseVoice zh | Whisper zh | 内容核对 |
| --- | ---: | ---: | ---: | ---: | --- |
| 1，`录音机-20261002-2226..m4a` | 3.35 s | 79.38 ms | 83.59 ms | 242.42 ms | 两种模型均保留“嗯，没有，最近还好” |
| 2，`录音机-20261002-2227..m4a` | 6.14 s | 88.59 ms | 95.16 ms | 435.84 ms | SenseVoice 正确；Whisper 三次均输出“睡补着” |
| 3，`录音机-20261002-2228..m4a` | 6.66 s | 89.81 ms | 88.84 ms | 344.60 ms | 两种模型均保留“不想自杀”；Whisper 使用繁体 |
| 4，`录音机-20261002-2228(1)..m4a` | 8.47 s | 104.31 ms | 105.22 ms | 494.39 ms | 保留“会想到伤害自己，但没有采取行动” |
| 5，`录音机-20261002-2229..m4a` | 7.79 s | 101.95 ms | 102.06 ms | 388.86 ms | 保留双重否定“没有不想吃饭”及句尾“没有失去兴趣” |
| 五合一，`录音机-20261002-2226.m4a` | 36.48 s | 303.35 ms | 303.20 ms | 1280.47 ms | 完整识别五句，见下述差异与接口限制 |

SenseVoice 的 5 条单句转写为：

1. 嗯，没有，最近还好。
2. 最近晚上经常睡不着，凌晨醒来以后就很难再入睡。
3. 我不想自杀，我只是有点难过，希望找个人聊聊。
4. 最近学习压力有点大，我有时会想到伤害自己，但没有采取行动。
5. 这几天睡眠不好，不过我没有不想吃饭，也没有失去兴趣。

Whisper 单句 2 的原输出为“最近晚上经常睡补着凌晨醒来以后就很难再入睡”，
没有自动修正为给定文本；这是一处词语识别差异，不能只看非空结果而判通过。
单句 3 的原输出为“我不想自殺,我只是有點難過,希望找個人聊聊”，语义与否定
保留，但繁简形式不同。其他单句主要为标点差异。

五合一的两种模型均按原顺序保留五句和关键否定词，不生成多个聊天回合。
第 4 句均输出“我有时候想到”，与测试稿及单句录音的“我有时会想到”不同；
不能仅凭给定稿确定是朗读差异还是识别差异，尚未人工回听确认。
SenseVoice 还有句间标点变化和末尾重复句号，按约定不润色。

**调整上限前的验证：** 五合一超过当时正式接口的 30 秒上限。
生产解码器返回 `AUDIO_TOO_LONG`；初次离线探针临时使用 60 秒解码保护上限，
给模型输入完整 36.48 秒波形，没有通过截断规避校验。因此表中五合一时间
属于离线模型测试，正式接口调整后的复测见下一节。

另用 TestClient 复用已加载的真实 SenseVoice，实际调用
`POST /api/audio/transcribe`：5 条单句均为 HTTP 200、返回上述完整转写，单次
本地请求耗时为 76.33～113.33 ms；单字“嗯”也返回 200；五合一返回 HTTP 422
及 `AUDIO_TOO_LONG`。ASR 后会话仍为 0 回合、没有消息。
这些录音文件未带真实采集时间轴；接口探针使用模拟 `capture_id` 和由解码
时长构造的起止值，仅验证协议与转写，不作为真实录音/视觉时间对齐证据。
未调用策略、评估模型或前端页面。原始真人音频不提交代码仓库。

### 上限调整至 60 秒后的正式接口复测

用户明确选择将录音上限改为 60 秒。已同步默认配置、环境示例、可配置最大
时长和接口文档，仍支持更低的配置值。文件限额、串行模型调用、队列上限与
超时保持原约定；不拆分录音为多个聊天回合。

在相同 GPU、真实 SenseVoice 默认 `auto` 模式下，使用 TestClient 运行实际
应用 lifespan 和上传路由，模型加载/预热约 13.61 秒，状态报告 `ready` 及
`max_duration_seconds=60`。调整后的结果为：

| 输入 | 正式接口结果 | 本地请求耗时 |
| --- | --- | ---: |
| 5 条原始单句 M4A | 均为 HTTP 200，保留上述完整转写 | 每句 87.48～106.13 ms |
| 36.48 秒五合一原始 M4A | HTTP 200，完整保留五句及关键否定词 | 313.14 ms |
| 衍生的完整 60 秒 WAV | HTTP 200，保留全部八句内容及句尾 | 464.47 ms |
| 声称采集区间为 61 秒的上传 | HTTP 422，`AUDIO_TOO_LONG` | 不调用模型 |

60 秒样本在内存中将五合一、单句 4、单句 5、单句 2 顺次拼接为 58.88 秒，
再加 1.12 秒尾部静音；它是边界探针，不是用户另外录制的自然 60 秒回答。
未裁剪原音频或把采样率标签冒充重采样，衍生原始音频没有写入磁盘。
正式接口返回的 `speech` 保留 60000 ms 结束值；整个 ASR 探针结束后会话
仍为 0 回合、没有消息。原文件的五合一措辞与标点差异仍如前述，没有事后
改写。探针使用模拟采集时间轴，仍不能证明前端与视觉的真实时间对齐。

自动化补充验证 60 秒完整波形全部送入模型，以及实际音频为 60.2 秒而客户端
声称 60 秒时仍被真实解码时长限制拒绝。客户端起止值不能绕过实际录音限额。

## 自动化检查与兼容性

项目测试共 **101 项通过**，涵盖原有聊天/评估及新增语音路径。真实模型识别
质量由上文的独立探针核对；常规测试使用识别和外部策略/评估替身，避免每次
运行下载权重或调用外部模型。

审核后修复了启动时读取项目 `.env`、异步转写路由等待同步会话锁导致的
事件循环阻塞，以及上传解析器与依赖下限不兼容三个问题。新增验证覆盖
仅通过 `.env` 启用 ASR、进程变量覆盖文件值，以及转写前后两次会话查询
均不阻塞事件循环。FastAPI 0.115.7 / Starlette 0.44.0 的最低 Web 依赖组合
与当时环境都通过全部 90 项测试；最低组合使用独立安装目录验证，没有
降级原环境。最低组合有一条第三方测试客户端的弃用提示，不影响测试结果。

后续复核发现上传完成后等待会话锁的请求未纳入容量限制，现已修复：路由
读取录音前预留槽位，上传、前后会话检查与识别共用 `ASR_MAX_PENDING`。
新增 11 项验证覆盖上传尚未完成及前后会话锁等待时，超额请求返回繁忙错误
且不读取请求体；上传取消、表单/会话/解码/模型失败及推理提交失败后的
容量恢复；运行中和排队任务被取消后仍保留槽位，直到工作线程处理结束。
指定 Miniforge 环境的全部 101 项测试通过；本次未重跑最低 Web 依赖组合
或真实模型质量测试。

截断文件可能在时长容差内被接受的问题按本次演示范围暂未修复；不能将
上述测试解释为已验证所有音频容器的完整性。

- 真实重采样、单双声道和末尾 flush；WAV、WebM/Opus、Ogg/Opus、MP4/AAC、
  MP3、FLAC 的真实编码文件解码；短录音不因长度被过滤。
- multipart 字段、大小、MIME 与实际格式、时间顺序/有限数值、时长匹配和
  超限校验；空音频、静音、无文字和超长转写有明确错误。
- 60 秒完整录音接受，超限采集区间拒绝，伪装采集区间的实际超限音频拒绝。
- 大于默认 spool 阈值的有效上传保持内存处理，未把原始录音写到临时磁盘。
- 单个模型实例串行调用，有限排队；正在推理与排队请求的超时/取消仍正确
  计入槽位，排队任务取出后跳过，不提前释放造成队列字节无限积压。
- 上传前限流，前后会话锁等待也计入容量；超额请求不读取音频，失败或取消
  后恢复容量，已提交推理不会因路由提前退出而释放仍在使用的槽位。
- 聊天成功后才保存消息与去重响应；策略失败可复用同一 ID 重试，并发重试
  仅产生一轮。改变原文本、时间或视觉内容返回冲突。
- 语音缺少本句视觉/音频特征时不读取上一轮状态；原文字聊天兼容。
- 简单评估与完整评估输入均保留原消息时间和录音标识；改写、重排、删减
  已有发言标识的历史或评估期间出现新聊天，返回冲突以避免覆盖记录。
- Git 差异空白检查通过；新增交付内容和本轮新增行未包含机器绝对路径或
  开发过程目录引用。
