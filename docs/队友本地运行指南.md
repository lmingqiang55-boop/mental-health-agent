# 队友本地运行指南

决策模型在每位队友自己的电脑上运行。项目不从 GitHub 下载模型，也不连接其他人的模型服务。
队友收到的 `policy-qwen3-8b-local-deploy.zip` 含训练后已合并 LoRA 的
`policy-qwen3-8b-Q4_K_M.gguf`；不要用普通 Qwen3 基座模型代替。

## 首次准备

1. 安装 [Windows 版 Ollama](https://ollama.com/download/windows) 并启动它。
2. 从 QQ 下载模型 ZIP，保留 ZIP 原文件，无需手动解压。
3. 在项目根目录创建团队环境（已经创建过就跳过）：

   ```powershell
   conda env create -f environment.yml
   npm --prefix frontend ci
   ```

4. 激活环境，用 ZIP 一键校验、导入模型并启动后端：

   ```powershell
   conda activate mental-health-agent
   python scripts/start_dev.py --model-package "D:\下载\policy-qwen3-8b-local-deploy.zip" --skip-install
   ```

   把引号内改为队友电脑上的实际 ZIP 路径。脚本检查 GGUF 大小和 SHA-256，
   使用仓库中的 `scripts/Modelfile-policy` 导入 `policy-qwen3-8b:latest`，
   然后启动后端。导入完成后会自动清理临时解压的 GGUF；保留 QQ 收到的 ZIP 备份即可。
   启动横幅应显示“本机 Ollama”和 `policy-qwen3-8b:latest`。

5. 另开终端启动前端：

   ```powershell
   npm --prefix frontend run dev
   ```

   打开 <http://127.0.0.1:5173>，输入一句话测试对话。

## 以后启动

已导入模型后无需再次传 ZIP：

```powershell
conda activate mental-health-agent
python scripts/start_dev.py --skip-install
```

`start_dev.py` 检查本机 Ollama 中是否存在指定训练模型；缺失时会报错，
不会自动改用关键词占位服务。手动启动后端时，`.env.example` 已默认指向
`http://127.0.0.1:11434` 和 `policy-qwen3-8b:latest`。

## 常见问题

- **提示找不到 Ollama**：先安装并启动 Ollama，重开终端。脚本也会尝试从
  Windows 默认安装目录查找 `ollama.exe`。
- **模型 ZIP 校验失败**：重新接收 ZIP。预期 GGUF 大小为 5,027,780,096 字节，
  SHA-256 为 `b5898652f3978d777137951f4a6384c9f8a7b73e832dbab59b5c2729696fbbd2`。
- **C 盘空间不足**：Ollama 导入后会在自己的模型库另存约 5 GB。
  可先把 `OLLAMA_MODELS` 用户环境变量指向空间充足的目录，再重启 Ollama。
  临时解压目录建在 ZIP 所在目录，也需要约 5 GB 空间。
- **只调对话链路**：首次安装 Python 依赖时可运行
  `python scripts/start_dev.py --model-package "ZIP路径" --core-only`，
  跳过语音识别和视觉模型的大型依赖。整套系统仍建议使用 `environment.yml`。
- **评估报告返回 503**：对话模型与评估服务分开；生成报告还需要在本地 `.env`
  配置 `DEEPSEEK_API_KEY`。真实密钥不要提交到仓库。
