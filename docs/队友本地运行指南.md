# 队友本地运行指南

## 一条命令

```powershell
python scripts/start_dev.py
```

就这一条。它会自动完成：

1. 没有 `.env` 就从 `.env.example` 复制一份
2. 缺依赖就按 `requirements.txt` 装。**注意**：团队 baseline 的 requirements 里有
   `torch==2.8.0+cu128`、`funasr`、`modelscope` 等，首次可能要几十分钟、数 GB。
   只跑对话与决策链路的话加 `--core-only`，跳过这 9 个重包（13 个包，快得多）。
   实测：不装它们后端照样正常启动，只有**语音识别**和**摄像头情绪**降级为不可用。
3. **自动挑决策源**，优先级从高到低：
   - `127.0.0.1:8001` 上已经有服务 → 直接复用
   - **局域网里有人共享模型**（自动发现，**不用填地址**）→ **真模型**
   - `--team` 指定的地址 → **真模型**
   - 本机 Ollama（`127.0.0.1:11434`）→ **真模型**
   - 都没有 → 内置占位服务（关键词规则）
4. 把选中的源统一接到 `127.0.0.1:8001`，并**自动填对真实模型名**
   —— 所以你的 `.env` 是什么内容都无所谓，**一个字都不用改**
5. 启动后端 `http://127.0.0.1:8000`

**队友全程不下载模型。** 整个流程里没有任何一步会拉取权重文件：要么连队长的
（局域网自动发现），要么用本机已有的，要么退回内置占位服务。没有 4.8GB 下载。

`Ctrl+C` 一次停掉全部子进程（转发器和占位服务都会跟着退出）。

前端另开一个窗口：

```powershell
cd frontend
npm install
npm run dev
```

## 队长分享模型（可选）

```powershell
python scripts/policy_tunnel.py host
```

队友**什么都不用填**，直接：

```powershell
python scripts/start_dev.py
```

`start_dev.py` 会在局域网里广播找一圈，自动发现你的机器并接上**真模型**。

- 你的机器要保持开机、这个窗口不能关，断了队友就返回 503。
- 多网卡（装了 WSL/VMware）或防火墙拦住自动发现时，用 host 窗口里打印的
  现成命令手动指定：`python scripts/start_dev.py --team 10.254.253.222:11435`
- 想限制来源：`python scripts/policy_tunnel.py host --allow 10.254.253.100`
- Ollama 没有鉴权，不加 `--allow` 就是同网段谁都能用。

### 队友不在同一个局域网？走 IPv6

`host` 是**双栈监听**（同一个端口同时收 IPv4 和 IPv6），所以队友换了网络也能接上：

1. 队长窗口的横幅里会列出几条现成命令，挑标记 `IPv6（跨网段可用）` 的那条，
   整条发给队友，例如：

   ```powershell
   python scripts/start_dev.py --team [2409:890f:4e08:38c1:fb14:3aee:6f59:f93c]:11435
   ```

2. 队友那边要有 IPv6。让他先确认一句：

   ```powershell
   curl -6 https://ifconfig.me
   ```

   有输出（一个 IPv6 地址）就能用；超时说明他没有 IPv6，那就只能同一局域网。

3. 队长这边要放行该端口的**入站**：

   ```powershell
   New-NetFirewallRule -DisplayName "policy tunnel 11435" -Direction Inbound `
     -Protocol TCP -LocalPort 11435 -Action Allow -Profile Any
   ```

要点：

- **IPv6 地址必须带方括号**（`[地址]:端口`）。地址内部的冒号会和端口分隔符冲突，
  不加方括号脚本会解析错。
- **不用端口映射**：IPv6 一般不做 NAT，那个地址本身就是公网可达的。
- **地址会变**：Windows 的 IPv6 后缀里有一种是"临时/隐私地址"，会定期轮换。横幅里
  两条 IPv6 都列出来了，优先用另一条（稳定后缀）；换了就重新看一眼横幅。
- 横幅里 IPv4 那几条只对同网段有效；`172.19.176.1` 是 WSL 虚拟网卡，队友连不上。

## 手动指定

| 需求 | 命令 |
| --- | --- |
| 自动挑（默认） | `python scripts/start_dev.py` |
| 借队长的模型 | `python scripts/start_dev.py --team HOST:PORT` |
| 关掉局域网自动发现 | `python scripts/start_dev.py --no-discover` |
| 强制本机真模型 | `python scripts/start_dev.py --policy-source local` |
| 强制占位服务 | `python scripts/start_dev.py --policy-source stub` |
| 缺依赖时先别装 | `python scripts/start_dev.py --skip-install` |
| 跳过 torch 等重包 | `python scripts/start_dev.py --core-only` |
| 换后端端口 | `python scripts/start_dev.py --backend-port 8080` |

只起单个组件也行：

```powershell
python scripts/dev_policy_stub.py                       # 只起占位服务
python scripts/policy_tunnel.py borrow --remote H:P     # 只起转发（本地 8001）
python scripts/policy_tunnel.py host                    # 只分享模型
python scripts/policy_tunnel.py host --allow 10.0.0.5   # 只允许指定队友
```

## 实测记录

| 场景 | 命令 | 结果 |
| --- | --- | --- |
| 自动发现本机真模型 | `start_dev.py --policy-source local` | 模型名自动识别为 `policy-qwen3-8b:latest`；动作 睡眠/食欲/兴趣；首轮 9.4s、之后 0.5s |
| 借用队长的模型 | `start_dev.py --team 10.254.253.222:11435` | 链路 `127.0.0.1:8001 → 10.254.253.222:11435 → Ollama`，真模型回答 |
| **局域网自动发现** | 队长 `policy_tunnel.py host`，队友 `start_dev.py`（**不填地址**） | 队友自动发现并接上真模型；两端日志都记录了发现握手 |
| 无模型自动回退 | `start_dev.py --policy-source stub` | 自动拉起占位服务，**不下载任何文件**；动作 睡眠/食欲/躯体症状 |
| **main 代码上的完整验证** | 队长端 `policy_tunnel.py host`（本仓库）<br>队友端 `start_dev.py`（**main 的代码**、不填地址） | 自动发现 → 接上真模型 `policy-qwen3-8b`；动作 睡眠/食欲/兴趣 全对 |
| 无 torch 也能启动 | 轻量环境(无 torch/funasr/emotiefflib) 起 main 后端 | `/api/health` 200，对话链路正常，仅语音/视觉降级 |
| **跨网段 IPv6 直连** | 队长 `policy_tunnel.py host`（双栈）<br>队友 `start_dev.py --team [2409:...:f93c]:11435` | 队友横幅显示 `决策源 真实模型 · [2409:...:11435]`；动作 睡眠/食欲/兴趣 全对；队长端记录到 IPv6 对端连接 |

以上验证全过程**没有改过 `.env`**——编排器用环境变量强制
`POLICY_API_BASE_URL` 与 `POLICY_API_MODEL`，覆盖 `.env` 里的任何写法。

## 已知坑

1. **首轮对话 6~10 秒**（模型冷加载），之后每轮 0.3~0.5 秒。模型空闲 5 分钟会被
   卸载，隔久了再发消息会再吃一次冷加载——不是故障。
2. **危机模式会在会话内闩锁**：一个会话里只要触发过危机，之后每一轮都返回
   `crisis_support`，哪怕你接着说"今天天气不错"。这是刻意的安全设计。
   **每测一个用例就新建一个会话**，否则会误以为"模型乱答"。
3. **危机关键词覆盖不足**：`backend/core/risk_engine.py` 的 `HIGH_SIGNALS`
   收录了「结束生命」，但**没有**「结束自己」「跳楼」「遗书」「安眠药」，
   这些会判成 `risk_level=low`、`requires_intervention=False`。
4. **占位服务不是模型。** `scripts/dev_policy_stub.py` 是关键词规则，不加载任何
   权重。它在「跳楼 / 遗书 / 结束自己」这类表述上**比真模型更准**（规则就是照着
   这些说法写的）。拿它演示、截图或写进答辩材料，等于把规则表的能力冒领成模型
   能力——**属于实质性虚假陈述**。凡涉及模型效果，一律走 `--team` 或本机 Ollama。
5. **重建 Ollama 模型必须用对模板。** 要换机器重建时，用仓库里的
   `scripts/Modelfile-policy`（训练时的 `qwen3_nothink`），**不要**用基座自带的
   `chat_template.jinja`（带 `enable_thinking` 分支）——提示格式和训练不一致，
   模型会输出 `<think>` 块，动作全乱。**队友用不到这个文件**，它只是重建时的记录。
