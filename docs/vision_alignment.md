# 摄像头、录音与评估对接（2026-10-03）

本文描述当前实现。`docs/api_spec.md` 是 HTTP 协议；原始语音质量实测保留在
`speech_validation_2026-10-02.md`。不把历史规划当作已实现功能。

## 当前链路

```text
摄像头开启 → 带采集时间的单帧分析 → 有界结构化帧缓存
用户按住录音 → MediaRecorder.start → 记录实际开始
用户松开 → MediaRecorder.stop → 等待末次 dataavailable 和 stop
                ├─ 完整文件 /api/audio/transcribe → ASR 原文
                └─ /api/vision/segment → 本句区间聚合并冻结快照
两路汇合 → /api/chat（同一 utterance_id、speech、vision_snapshot）
聊天成功 → 保存 user + assistant
点击生成结果 → /api/assessment（session_id）
从消息上已绑定的逐句快照生成会话汇总 → 评估 Agent → 页面
```

文字输入也使用句级快照：聚合本次开始输入到发送的区间，最长回看 60 秒；
它表示输入期间的画面，不表示语音区间。摄像头关闭时文字输入明确发送
`vision_snapshot: null`，不会借用旧帧。

## 共同时间轴与采样

- 前端记录 `performance.now()` 的毫秒数，权限等待不计入录音。
- 每次会话及摄像头重新开启生成新的 `capture_id`；录音使用开始时的 ID。
  录音和发送处理期间禁止切换摄像头。
- 摄像头每 500 ms 尝试采样，仅一个帧请求在途；画面按比例压缩至最大
  640×480。慢推理会降低实际帧率，不堆积原图。
- 单帧请求最多等待 10 秒，超时取消请求并释放前端采样位置，后续采样自动继续。
  关闭摄像头会立即清理请求及超时定时器；迟到响应不影响新请求或已冻结快照。
  取消前端请求不保证服务端已经开始的模型推理立即停止。
- 每帧有唯一 `frame_id` 和拍摄时刻 `captured_at_ms`，在画布取帧前记录。
- `VisionState.timestamp` 仍为服务端 UTC；不能拿它与录音毫秒数比较。
- 服务端保留最近 512 条结构化帧和 512 条实时状态。原图、原始录音不持久化。
  这是单页单采集客户端、单后端进程的演示实现。

## 摄像头生命周期

`POST /api/vision/capture` 接收 `session_id`、`capture_id`、整数 `generation`
和 `active`。每次开启/关闭递增 generation；迟到的旧命令不覆盖新状态。
相同 generation 的相同命令可重试，不同内容返回 `VISION_CAPTURE_CONFLICT`。

关闭会清空最新视觉状态。停止或换代后，旧帧在推理前和写回前都会被拒绝
（`VISION_CAPTURE_INACTIVE`），不能重新污染状态。前端同时停止所有 tracks、
定时器和在途帧请求；权限弹窗尚未返回时也可取消。重复开启不会创建两个流。

## 区间聚合与重试

`POST /api/vision/segment` 使用 `session_id`、`utterance_id`、`capture_id`、
`start_ms`、`end_ms`，只选同一 ID 上 `[start_ms, end_ms)` 的帧。区间须为
正时长且不超过 60 秒。前端最多等待区间内已发出的帧 3 秒，再请求冻结。

- 没有帧：快照为 `null`；有帧但都无人脸：`face_detected=false`，指标为 `null`。
- 每项指标只平均有效人脸帧上已有的数值，不把缺测当作 0。
- 情绪为有效帧中出现最多的类别；并列时取按采集时间首次出现的类别。
  `emotion_confidence` 是有效数值的均值，并非新的校准置信度。
- 返回 `frame_count`、`valid_frame_count` 和 `vision_snapshot`。
- 第一次结果按 utterance_id 冻结；同区间重试返回同一结果，包括首次缺测。
  晚到帧不改变它；改区间返回 `UTTERANCE_CONFLICT`。
- 同一帧重试不会重复统计；更换图像或采集时间返回 `VISION_FRAME_CONFLICT`。
- 聊天使用冻结结果时必须保留快照及录音区间。聊天失败只重试原请求。

前端在等待权限时松开、指针取消、窗口失焦时取消录音；最长录音自动结束并
发送。重新开始、离页或手动取消使旧结果失效。处理中禁用新输入和评估，
发送聊天前可取消，始终可重新开始。聊天已发出后不承诺撤回；发送状态不明时只能复用原请求重试确认或重新开始。失败后保留当前录音/文字和已完成步骤于内存，提供
“重试本次输入”或“重试发送”；放弃后释放引用，不落盘。

## 评估边界

简单评估只发送 session_id。后端从用户消息的逐句快照生成 `vision_summary`，
不从原始帧日志猜测对应关系。`sample_count` 是有快照的用户发言数，
`valence_trend` 是这些发言中有效效价按消息顺序构成的序列；
`face_present_ratio` 是这些句级样本的有效人脸比例，不是逐帧时长占比。
不同长度的发言按句等权，不按帧数加权。
有句级样本但全部无人脸时，`face_present_ratio=0`，情绪指标保持 `null`；
没有任何句级样本时，人脸比例保持缺测。

完整 `evaluation_input` 仍支持可信上游导入。既有消息按原顺序和文本保留
录音元数据与视觉快照；省略或 null 不清空已绑定快照，改写它返回
`HISTORY_CONFLICT`。省略会话汇总时由已绑定快照构造；外部显式汇总仍支持。
允许替换无发言标识的历史时，新历史无视觉且未提供新汇总会清空旧汇总；
同一段历史重试仍保留已提供的汇总，已有发言标识的历史继续禁止替换。
评估期间发生新聊天时返回冲突，不将旧报告链接为最新会话结果。

旧无时间字段的 `/api/vision/frame` 可用于展示，不能参与区间聚合。
旧文字请求仍可读取最近 5 秒的视觉状态作规则式风险辅助，但不把它保存为
句级证据。当前决策模型只读取对话文字，视觉用于风险辅助及最终评估。

## 模型和限制

保留 EmotiEffLib 的情绪/valence/arousal 适配；真实模型缺少眼动、微表情或
参与度时留空。人脸检测器不可用时明确失败，不把整张场景图当作有效人脸。
模型初始化和同实例推理有锁；无有效人脸的完整帧不会与上一帧合并。
`VISION_PROVIDER=mock` 仅用于虚构数据演示，真实分析需设为 `emotiefflib`。

本次没有更换模型，也没有引入新的 GitHub 模型依赖。当前仍需真人设备验收：
人脸角度、遮挡、光照、不同浏览器录音格式、短回答、否定词、句尾和整体延迟。
自动化与虚拟设备联调只验证接线和生命周期，不证明真实模型准确率。
