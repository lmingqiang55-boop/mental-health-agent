# 前端交接文档

交接对象：负责 `frontend/` 的同学。

这份文档是**总入口**：怎么把整套环境跑起来、前端现在做到哪一步、接下来按什么顺序做。
接口字段不在这里重复——每个子系统的完整规格都有专门的文档，第 3 节会逐个指过去。

---

## 0. 现状一句话

后端（对话、评估、语音、视觉、治愈 Agent）已完成并可用；前端三个页面骨架已经接通，
**但评估报告的正文没有显示**，**治愈 Agent 没有任何前端入口**。这两块就是接下来要做的事。

## 1. 把环境跑起来

### 1.1 后端 + 决策模型（一条命令）

首次从 QQ 收到决策模型 ZIP 后，在本机安装 Ollama，并在已创建的团队 Conda 环境中运行：

```powershell
conda activate mental-health-agent
python scripts/start_dev.py --model-package "D:\下载\policy-qwen3-8b-local-deploy.zip" --skip-install
```

它会校验并导入训练模型，然后启动后端 `http://127.0.0.1:8000`。
以后运行 `python scripts/start_dev.py --skip-install` 即可；不需要改 `.env` 中的决策模型配置。
完整步骤见 [队友本地运行指南](队友本地运行指南.md)。

### 1.2 前端

```powershell
cd frontend
npm install
npm run dev        # → http://127.0.0.1:5173
```

`vite.config.js` 已经把 `/api` 代理到 `http://127.0.0.1:8000`，所以前端一律用**相对路径**
`/api/...`，不要写死后端地址。所有请求都走 `src/api/client.js`，页面里不直接 `fetch`。

### 1.3 三个后端开关（决定你能测到哪一步）

| 能力 | `.env.example` 默认 | 要真用需要 |
| --- | --- | --- |
| 决策模型（下一步问什么） | 本机 Ollama `127.0.0.1:11434` | 首次用 `start_dev.py --model-package` 导入训练模型 |
| 对话回复文案 | 本地模板，**不需要 Key** | 见下面说明 |
| 综合评估（出报告） | 无 Key | 本地 `.env` 填 `DEEPSEEK_API_KEY`，否则 `503 EVALUATION_UNAVAILABLE` |
| 语音识别 | `ASR_PROVIDER=disabled` | 装 torch/funasr（即去掉 `--core-only`），并设 `ASR_PROVIDER=sensevoice`、`ASR_DEVICE=cuda:0` |
| 摄像头情绪 | `VISION_PROVIDER=mock` | 装 emotiefflib/opencv，并设 `VISION_PROVIDER=emotiefflib` |

关于"对话回复文案"：普通轮次的 `reply` 是**按决策动作查本地模板**生成的
（见 `backend/policy/reply.py` 的 `QUESTIONS` 表），不消耗任何外部 API；
只有危机轮次会走 LLM 客户端，而它默认是 `MockLLMClient`，**同样不需要 Key**。
所以：**不做评估、只调对话页，你一个 Key 都不需要。**

要做 P0 的评估报告页面，你需要能产出一次真实评估——那就得配 `DEEPSEEK_API_KEY`。
暂时没有也能开工：`docs/examples/assessment_response.json` 是一份完整的虚构响应，
可以直接当静态模拟数据把页面做出来。

## 3. 接下来做什么（按优先级）

### P0 — 评估报告页面

**这是最大的缺口，也是最有把握做的一块：完整规格已经写好了，照着做即可。**

👉 [评估结果页面交接文档](assessment_output_page_handoff.md)

那份文档给了：展示顺序、每个字段的类型/范围/推荐文案、关注等级映射表、
加载与错误处理、以及一份可当模拟数据的示例响应。

现在 `AssessmentResultView.jsx` 只做了其中一小部分，需要补齐：

- `result.report.overall_status.summary` 总体说明
- `result.report.primary_concern` 最值得关注的方面
- `result.report.key_findings` 关键发现（2～4 条）
- `result.report.multimodal_observation` 多模态观察
  ——`consistency_level` 为 `unknown` 时分数是 `null`，**不要显示成 0 分**
- `result.report.trend_and_suggestions` 趋势解读与建议
  ——没有纵向依据时 `trend` 是 `unclear`，**如实显示，不要虚构趋势**
- `result.created_at` 生成时间

**老师端也要同步补**：`TeacherPage.jsx` 的详情页里同样写着"报告文案和建议尚未接入"。

### P1 — 治愈 Agent 前端入口

后端已完成（三个接口都在），README 里写明"前端入口由页面负责方对接"。**前端一行都没有。**

👉 [治愈 Agent 后端与接口交接](healing_agent.md)
（其中的 **「前端接入约定」** 一节是硬要求，错误码表是 `HEALING_*` 系列。）

那 6 条约定里最容易踩的两条：

1. **评估成功后才由学生点独立入口调用 `/start`**，不要自动进入。
2. **陪伴回答只发 `/healing/chat`，不能调 `/chat` 或 `/assessment`，也不能清空筛查结果**——
   否则会把陪伴消息当成筛查输入评进去。

### P2 — 老师端补全

- 写跟进记录（`addNote` 已封装，缺界面）
- 家校沟通（`sendCommunication` / `listCommunication` 已封装，缺界面）
- 学生历史（`getStudentHistory`）

## 4. 验收清单

结果页面部分（摘自[评估结果页面交接文档](assessment_output_page_handoff.md) 第 5 节）：

- [ ] 用示例 JSON 能显示五维分数、关注指数、两套等级、生成时间；空数组不渲染成空白标签
- [ ] 报告正文、关键发现、多模态观察、趋势与建议都显示
- [ ] `unknown` / `unclear` 如实展示，不虚构趋势或视觉一致性
- [ ] 页面能区分**对话接口的本轮 `risk`** 和**评估接口的最终 `result.risk`**
- [ ] `503` / `404` / `422` 显示明确错误，**不把上一份结果显示成本次结果**
- [ ] 文案称"初步筛查""关注提示"，不称"确诊""抑郁症严重程度"

治愈 Agent 部分：

- [ ] 评估成功后才出现陪伴入口
- [ ] 陪伴消息不影响筛查结果，返回筛查时原对话还在
- [ ] 404 引导重新进入，409 提示状态已变化后读取当前陪伴

通用：演示数据只用虚构对话。

## 5. 前端相关的坑

1. **决策模型没接上时，对话每一轮都会返回 `503 POLICY_UNAVAILABLE`。**
   后端**没有规则回退**——这是刻意设计，不会偷偷改用固定问题。所以调试前端之前，
   先按 §1.1 把模型接上，否则你会以为是页面坏了。
2. **评估不会自动触发**，必须学生点「生成初步结果」；且至少要有一条已保存的用户消息。
3. **会话在后端内存里，约 2 小时 TTL；评估结果存本机 SQLite，后端重启仍在。**
   清除浏览器数据会丢失 `localStorage` 里的匿名标识
   （键名 `mental-health-agent:student-ref:v1`，用于查最近 3 次结果）。
4. **`overall_level`（关注等级）和 `risk_level`（风险等级）是两套独立结果**，
   不能互相推导，也不要合成一个显示。
5. **五维分数越高表示越值得关注，不是健康分。** 页面别写成"情绪 80 分"。
6. **首轮对话会因为模型冷加载慢 6～10 秒**，之后每轮 0.3～0.5 秒。
   模型空闲 5 分钟会被卸载，隔久了再发消息会再吃一次冷加载——不是卡死，别急着加超时提示。
7. **语音和摄像头没配好时后端会降级**，页面必须能继续走文字。
   `StudentPage` 现在已经是这么处理的，改动时别破坏它。
8. `npm run dev` 绑定 `127.0.0.1`；要给别人访问得改 `vite.config.js`，
   同时别忘了后端的 `CORS_ORIGINS`。
