# 小晴对话提示词优化说明

日期：2026-10-20。基线：`a0dea57`，含第 25 轮补问提醒、第 35 轮收尾。
当前修改分支：`codex/natural-dialogue-prompts`。

目标是改善竞赛演示中的具体回应、跨轮承接和口头表达。修改入口为
[`backend/prompts/dialogue_prompt.py`](../backend/prompts/dialogue_prompt.py)。

## 参考资料与采用范围

1. [Anthropic：Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)。
   官方指南建议明确描述预期行为，使用贴近应用且彼此多样的示例，并清楚区分示例、背景和指令。
   本次采用这些通用提示词设计方法；具体到 DeepSeek 的效果需要实际对照验证。
2. [Liu 等，ACL 2021：Towards Emotional Support Dialog Systems](https://aclanthology.org/2021.acl-long.269/)，
   [论文 PDF](https://aclanthology.org/2021.acl-long.269.pdf)。
   ESConv 将支持对话中的提问、澄清与转述、回应感受、提供信息和建议等方式分别标注。
   本次借鉴“依据上下文选择回应方式”，避免整段对话只重复一种安慰加追问的结构。
   论文还包含自我披露；小晴的版本只允许使用真实输入中的事实，不模仿真人编写个人经历。
3. [Rashkin 等，ACL 2019：Towards Empathetic Open-domain Conversation Models](https://aclanthology.org/P19-1534/)。
   EmpatheticDialogues 的对话以具体情绪情境为背景。本次据此把演示目标落到“回应用户遇到的具体事情”，
   而不只要求语气温柔。这里是提示词设计上的借鉴，不代表取得了论文的实验结果。

中文表达还按本地 `humanizer-zh` 技能检查了套话、机械复述和句式重复。

## 原有提示词的问题与调整

原有规则既要求情绪明显时先用一条消息共情，又强调必须执行指定话题；这种组合容易引导出
“复述感受—泛泛安慰—下一个问题”的固定结构。短句分支也会把缺少情绪词的短发言统一要求
直接推进，而“现在怎么办”“这算严重吗”本身就是应该先回应的求助或反问。

新版的主要调整：

- 固定角色为温和、直接、有分寸的 AI 助手。普通交流使用口语，被问身份时如实说明。
- 先结合上一句理解本轮发言的用途，再选择回应、澄清、追问或暂时不提问。
- 对具体处境表达关切，允许关切体现在贴切的问法里，取消每轮额外加安慰句的要求。
- 直接疑问、求助和纠正优先得到回应；“不知道”保留不确定含义，可以把原问题问具体。
- 使用前文已知的时间、频率和经历；被指出问重复时，简短承认并使用已有答案。
- 换题使用简短过渡，不编造症状之间的因果关系。新评估问题仍围绕指定话题。
- 收尾可以提到用户实际说过的一两件事，再引出初步结果。

仍保留每轮最多一个主要问题、1～3 条完整消息、回应与追问分开气泡，以及现有视觉表达边界。
后端轮数、调度、安全入口与评分公式没有因本次表达优化而变更。

## 表达示例

新系统提示词内含十组自行编写的示例：情绪倾诉、明确短答（时间和频率各一组）、直接反问、拒绝回答、具体求助、
跨轮承接、自然换题、纠正重复提问、个性化收尾。“具体求助”和“跨轮承接”两组新增示例来自首轮实测发现的问题。
示例用标签与实际上下文分开，并明确其中经历不属于当前用户。

例如，以下是编写进提示词的风格示范，不是本次真实模型返回：

> 已知用户说睡不好已有两周，助手又问持续多久。用户：“刚才说过了呀。”
>
> 对，你说是两周了，我问重复了。
>
> 这两周里，一周大概有几晚会睡不好？

不同示例包含一条或两条消息，也包含不提问的回应，减少示例自身形成统一模板的机会。

## 可重复的真实模型对照

[`scripts/compare_dialogue_prompts.py`](../scripts/compare_dialogue_prompts.py) 提供 10 个独立场景，
覆盖情绪开场、短句反问、跨轮承接、纠错、求助、拒答、不确定、信息短答、允许的视觉关切及收尾。
它记录新旧提示词的哈希、模型参数、原始回复和耗时；每个输入每版只生成一次。
默认只构造提示词，添加 `--live` 才调用模型。

离线运行：

```powershell
python scripts/compare_dialogue_prompts.py --baseline-ref a0dea57
```

真实对照命令：

```powershell
python scripts/compare_dialogue_prompts.py --baseline-ref a0dea57 --live --out .codex-runtime/dialogue_prompt_comparison_round1.json
```

这项测试会向项目配置的 `https://api.deepseek.com` 发送旧版与新版系统提示词及虚构对话，
首轮共 20 次调用并消耗 API 配额。用户明确同意后，首轮 20 次调用全部成功；模型为项目配置的
`deepseek-flash`，temperature=0.5，max_tokens=300。首轮对照及后续复测共 35 条完整回复与逐项判断见
[`dialogue_prompt_ab_20261020.md`](dialogue_prompt_ab_20261020.md)。

首轮没有发现全面胜出：候选版在不确定回答和个性化收尾上有改善，但简短求助时依然用新问题
替代帮助，拒答后也会继续问同一领域；全部九个非收尾场景都输出了两条消息，句式仍然单一。
跨轮承接还把用户没有明确说过的“犯困”当成已知信息。

据此再次修订提示词：明确困难时先给一个可选步骤再停下；拒答时本轮只接纳、不提问；
信息短答不必复述或评价；可能的症状以问题核对，避免默认用户已经出现。补充求助与跨轮示例。

第一轮修订的五次补测全部成功：明确求助时给了步骤，
明确拒答后停下，跨轮提问不再默认犯困，视觉信息表达更简洁；信息短答仍有复述和评价。

最终修订进一步明确：信息短答只用一条具体问题推进，增加频率短答示例；纠错示例沿用
“睡不好”的原有范围，避免擅自收窄为入睡困难。最终版对五个关键原场景及五个新措辞场景各调用一次，
十次全部成功，原始记录的系统提示词哈希与当前文件一致。

最终版在纯信息短答、纠错、明确拒答及不默认用户犯困的场景中符合预期，求助时会先给具体建议。
但建议后仍可能追加问题；对于“先别聊同学的事了，可以吗”这样的婉转拒答，仍可能马上问同一领域
的其他问题。新措辞场景也出现了替用户概括挫败感、身份答复后转入评估稍生硬的情况。
这些表现作为当前限制保留，不宣称提示词已经稳定解决。

最终复核采用固定五次关键场景加五次新措辞的直接生成，没有自动重试或重写。
本次实际 API 调用总计 35 次，全部使用虚构输入；最终文件通过 128 项离线回归及提示词组装检查。

问号数量和消息条数只作辅助指标。每个输入每版只生成一次，且未经过 Safety、策略调度、
路由和回复重写，也未测试真实摄像头、语音或连续 25～35 轮对话，不能据此宣称稳定的自然度提升、
临床效果或完整系统验收。
