日期：2026-10-06。已将成人支持从主要依赖上游传参，改为需要时在陪伴对话中确认；`background.adult_support_available` 继续接受可选的明确值。公开接口和响应字段不变，前端通过现有 `/api/healing/chat` 回答即可。运行中的后端需要重新加载本次代码。

## 当前行为

| 条件或回答 | 行为 |
| --- | --- |
| 已明确有成人支持 | 可以展示适合的方法，仍保留来源的成人指导及其他前提 |
| 已明确没有成人支持 | 排除成人指导方法，可以选择自主方法 |
| 未知，但只选中了自主方法 | 不询问成人支持 |
| 未知，实际选中了成人指导方法 | 暂存候选，不展示其步骤；问一次“你身边有没有一位你信任、愿意也能陪你试试的大人？” |
| 紧接此问题回答“有” | 核对其他条件后启用对应方法 |
| 回答“没有” | 不启用成人方法，继续陪伴并可选择自主方法 |
| 回答“不确定”、拒答或没有回答此条件 | 保持未知，本轮不反复追问；继续陪伴并可选择自主方法 |
| 后来明确说“现在老师能陪我了”或“现在妈妈不能陪我了” | 更新当前条件，重新筛选，覆盖之前相反的传参或回答 |

首次进入可以复用当前筛查文字、具体困扰或限制中明确的当前支持条件。“我有父母”只说明家庭成员存在；与本问题无关的“有/没有”、历史支持、假设或疑问不作为当前成人可用的确认。识别是有限中文表达的保守规则，不宣称实现任意自然语言背景抽取。不同成人的条件分别处理，某个具体方法的困难继续按原方法关联，不扩展成全局成人不可用。

不确定在记录及模型上下文中仍是 `null`。筛选方法时暂不允许未经确认的成人方法，不把这条执行规则冒充成“学生没有成人”。确认可用也不表示成人已经在场、学生已经准备或尝试，不能据此产生执行或效果反馈。

本轮最多两个活跃方法。成人条件恢复时复用原建议关联和反馈，不复制建议；已经明确拒绝或无效的方法仍受原排除规则约束。更换关注方向后，不启用旧方向暂存的成人方法。

风险求助、暂停和结束仍按既有优先级处理。拒绝回答成人问题不等于结束整段陪伴；明确“不想聊了”仍可结束。生成失败保留已接受的原状态，同一消息可幂等重试；新风险会阻止迟到的普通结果覆盖求助状态。成人问题回答后，GET和恢复报告不继续展示已回答的旧问题。

## 接线和状态

- `backend/healing/adult_support.py`：提问常量、语境关联识别、筛选背景及模型上下文快照。
- `backend/models/healing.py`：私有 `AdultSupportState` 保存可用性、来源、原话、轮次、是否已问、待确认候选及受条件停用的建议关联。
- `backend/healing/agent.py`：在实际方法选择之后决定是否提问；回答后筛选、启用或停用方法，隔离条件回答与执行反馈。
- `backend/healing/suitability.py`：条件核对使用当前明确成人状态，同时保留其他限制和原方法关联。

成人条件只存在当前进程内陪伴状态中；没有新增数据库表或修改原持久评估记忆。评估绑定不变，年龄和年级仍从绑定记录读取，偏好、重要经历等其他字段的完整自动提取和长期保存不在本次范围。
